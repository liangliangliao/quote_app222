# 六模块：用户主导的需求发现与知识应用

基线：`43efa7b`（PR #161）。本次保留 v2.7 的目标合同、计划版本、学习窗口、六节点循环与提醒；在新目标入口加入两轮明确选择，不把模型推测直接写成用户目标。

## 可见流程

1. 用户输入现实问题。文本模型提出有区别的显性/潜在需求和问题候选，附原话、理由、可能目的和自我核对问题；JEV 按相关程度排序，展示前 20 项（不足时不伪造候选）。候选不是诊断或“真实意图”的判定。
2. 用户多选、补充或改写自己的需要，没有默认勾选。只以这轮选择匹配知识。
3. 本地从整个当前知识库召回相关条目，并逐项需求补充召回；JEV 分批比较召回池，返回前 5 项。展示分数、来源、方法、前提和边界；这不是对全库逐条推理后得到的全局排名，也不是经过实证校准的概率。
4. 用户再次勾选知识。文本模型只能依据两轮选择生成完整方案，并说明每个步骤回应哪项需要、用到哪项知识、如何观察效果、何时停止。没有第二次选择不能生成方案，没有最终确认不保存为旅程依据。
5. 确认后进入原有信念→目标→行动→结果→复盘→改变流程。选定知识进入节点指导和行动编译，新的计划/改变优先于最初方案；ACT 保留已确认条件。旧预测和现实事实不重写。

已有目标的现实补充仍接续当前节点，避免每次记录结果都被迫重新选择。目标页面可随时进入“重新梳理需求与选择知识”。中途退出保存草稿；输入改变后不复用旧选择。

## 可用性与请求控制

- 目标、节点、知识应用、行动确认、结果记录、复盘出口等表单使用可编辑草案。主要字段先显示，其余详情可展开。现有记录和用户刚编辑的内容不被异步响应覆盖。
- AI 内容、本地规则、默认示例和用户编辑均标来源。缺少实际测量、他人意愿或结果时保留“未知/尚未记录”，不靠虚构数值填满表单。
- 成功的节点指导、行动分析、复盘、表单和发现流程结果缓存在 SQLite。键包含实际上下文、周期/版本、相关知识版本、模型配置和结构版本；仅浏览不改键。失败/降级结果不作为 AI 成功缓存。
- 提供显式重新分析按钮。同一请求在执行中合并；重进页面或进程重建可复用成功结果。重新生成候选后清理过时的 AI 选择；重新匹配知识后重新让用户选择。
- JEV 不可用时显著说明降级：需求排序为 LLM 粗估，知识为本地召回且不显示伪造的 JEV 分数。可配置后手动重试。

## 已定位的错误与统计口径

- 首次旅程也携带 `journey_context`，旧校验错误地把任何上下文都当“上一轮”，因而要求首轮填写 `learning_applied`。现仅在存在已决定的前轮试验时要求承接学习。
- 结构化回复允许完整 JSON 前后的说明/代码围栏。由运行时确定的缺失路由回显可补齐；出现错误回显、未授权来源、编造事实或越过边界仍拒绝采用。格式失败有一次带具体原因的修复请求，服务故障不做无效的盲重试。
- 复盘允许模型逐字引用真实记录的片段，但保存时恢复完整原始事实；不能新增或改写事实。错误原因区分超时、结构、来源、事实和安全条件。
- “六模块使用分布”分开显示节点执行、已保存 AI 节点指导、知识采用。读取已有节点日志和各模块知识来源，不再只按 Trial 的主模块计数；重复查看或缓存命中不增加节点指导次数。这不是网络 API 请求次数或用户学习效果评分。

## 验证边界

回归测试覆盖数据库持久化、两轮选择门、所选知识约束、跨轮计划、缓存命中/失效/刷新、表单异步覆盖保护、首轮校验、事实完整性和六模块统计。模型与 JEV 测试使用可控响应，不能据此宣称真实供应商的输出质量、所有潜在需求覆盖或真机后台行为已获得保证。发布时另核对相同提交的 CI 与 APK 构建。
