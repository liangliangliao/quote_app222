# 意志之镜 v2.8 开发交付

本次沿用「发现之旅 → 意志之镜」唯一入口，在原 `wm_goal.id` 上加入完整课题工作台。原 V4/V5 的今日练习、Deep Why、探针、Real-Me、七日实验、知识库与隐私设置保留。开发基线为 `main@ec8f7749`，分支 `feature/will-mirror-v28-discovery`。

已经能实际操作的闭环：一句话建课题 → 分开记录事实/信念/感受/未知 → 欲求候选与正反理由 → Top5 与开放路线 → 封存事前计划 → 真实现场核实 → 独立记录选择、准备、尝试、结果与后续体验 → 多轮时间线 → 有证据的个人原则候选、认可、现场复用、反例修订和撤回。

**本交付不等于 T1—T366 全部通过。** 功能、测试、模型语义质量和真机验证分别记录。参见 [逐项验收矩阵](acceptance.md)、[基线与实现审计](audit.md)、[演示步骤](demo.md)、[验证记录](validation.md)。原则与能力仍是可检验、可修订的经验，不是人格诊断或成功概率。

Vault schema 1 → 2 只增加 `wm_case_state`（外键 `goal_id` 指向原目标），不重建或清空旧表。聚合 JSON 加密后持久化，复用现有 Android Keystore；时间与关系 ID 是元数据。乐观锁拒绝过期的异步 AI 回写。旧证据、事件、原则版本和封存 payload 不可由普通保存改写；隐私撤回走专用事务，清除派生内容并使其他课题引用失效。旧经历按用户选择关联，保留原 ID 和发生时间，其“被本轮认识的时间”是现在，不冒充原 T0 已知。

本实现复用现有 sqflite/Vault，没有另建 PRD 示意中的 Drift 数据库或另一个同名业务。同步仍为原设置；v2.8 敏感聚合不会写入旧同步 outbox。主动导出的明文副本由用户保管，后续撤回不能收回已导出的副本或已发送的远程请求。

## AI 与评分

默认本地可用，清楚显示只有 3 条规则候选，不假称生成 50 条个人化动机。用户每次选择可发送的证据并确认后，才复用宿主已配置的 AI Provider：先生成欲求/路线/认识候选，再分三批扩展至最多 70 条语义候选；引用、状态、取值与安全边界校验失败则丢弃。去重不足 50 条时如实说明。词面相似度与模型 semanticKey 是工程近似，未用真实跨领域样本证明语义去重质量。

排序使用固定四维 0–4 量规：个人适配 .35、证据质量 .25、决策重要性 .25、情境相关性 .15。缺失个人证据或事实来源时不补零、不计算假总分；风险理由可作为待核实项保留。置信度与事实质量独立。可调整权重，近分提示顺序不稳定。Top5 是理由集合，不能批准尚未核实或已阻断的路线。

已查阅 OpenAI 官方公开 Beta `POST /v1/decisions` 与 `gpt-6-luna` 契约；客户端和代理都有模拟契约测试。代理只持有服务端 OpenAI 密钥，移动端仅保存独立的用户服务令牌。生成环节沿用宿主 BYOK 模式，没有加入开发者密钥。**尚未部署代理或使用真实收费接口调用。** 无配置、网络失败、拒绝、错位答案均明确降级，不冒充在线评分。

所有 `will_mirror.*` / `unified_ai.will_mirror.*` 请求、响应及异常在宿主日志入口被排除，避免加密资料另存进普通明文日志。

## 尚待深化与验收

- 真机通知的冷启动、重启恢复、省电延迟、权限拒绝、TTS 可用性，以及 TalkBack 全流程；Widget 已覆盖手机窄屏和 1.4 倍文字，但不能替代真机验收。
- 真实模型的跨领域个性化、50–70 条候选质量、语义稳健性、安全/专业高风险场景专家审阅与长期效果；不会用模拟输出宣称已完成这些验证。
- PRD 的高级关系图/之字形地图、《动机之潮》动效、资源互斥图、长期校准统计与多原则冲突自动推理。当前采用原课题内的卡片、关联 ID、事件时间线与用户核实。
- 功能适配和可改变性已能记录证据、条件与下一步；支持变体的自动搜索、职业机会推荐和自动跨课题模式发现仍为部分实现。原则只有在用户主动选择并核实条件后复用，不自动把历史经验当作新课题事实。

上述边界逐项列入矩阵，不将旧 V5 的测试通过等同于 v2.8 全部验收。
