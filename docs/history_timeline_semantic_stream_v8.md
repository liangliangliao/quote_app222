## 时间线

历史页“时间线”采用淡紫色景深页头、沙漏和叔本华肖像、圆角页签、日期胶囊、连续弯曲丝带与名言卡片。复用现有本地肖像，装饰由 Flutter 绘制，不产生 AI 或图片网络请求。

最近日期在前，同一天内按记录时间从早到晚；列表的物理洗牌不影响时间判断。时间来自 inserted_at，无法解析时回退到 created_at，并按设备本地日期分组。未标时间的记录单列在末尾，不补造时间；相同时间的记录保持输入顺序并标为“同刻”。

默认以最近一天的第二个节点为“此刻”（仅有一条时选第一条）。点选圆点可换参照，前一刻、后续、前一日等标签相对该参照计算，不把它说成系统当前时间。只展示先后，不推断思想之间的因果。

保留搜索、跨搜索选择比较、加号/取消选择、打开原文与认知阅读、加载更多和刷新机制。大字体时调整卡片内的作者与按钮排列，避免强行缩小正文。

## 概念图响应

截图是 HTTP 客户端在收到完整响应头前断线，没有可据此判断认证、额度或模型权限的 HTTP 状态。原实现对 JSON 任务关闭流式响应，完整树与圈的长生成容易在等待最终响应时遭遇连接中断；仅凭截图不能确定手机、VPN、网关或服务端中的具体断点。

针对 `cognition.semantic.v*`，Azure/OpenAI 兼容的文字请求同时保留 JSON 输出约束与 stream:true；收集完整答案后才交给概念图解析器。其他业务的 JSON 传输保持既有规则，Azure Claude 仍使用原有 Anthropic 非流式接口。

参考微软对应版本的[Chat Completions REST 文档](https://learn.microsoft.com/en-us/rest/api/microsoftfoundry/model-inference/get-chat-completions/get-chat-completions?view=rest-microsoftfoundry-model-inference-2024-05-01-preview)：stream 与 response_format 是两个参数；输出达到上限时正文可能被截断。因此接收器分别处理正文分片、结束状态和结构校验。

- UTF-8 增量解码、SSE 多行 data 与保活消息；只收集最终正文，不把 reasoning_content 当作答案。
- 支持 Chat Completions 和 Responses 正文事件；最终完整事件不重复追加。兼容忽略 stream:true、仍返回普通 JSON 响应的网关。
- 断流产生的半截 JSON 不进入格式修复、不写入缓存。已完整收到 JSON 而仅缺少尾部结束标记时，保留已有完整结果。
- 明确的输出截断和内容拒绝给出对应提示。断线时保留旧树与圈，用户可手动重试。
- 该任务的输出上限取请求值、用户全局较小设置、10000 三者的最小值，避免全局 64000 等大值放大概念图生成。
- 传输失败不叠加全局自动重试；保留既有的明确路径不支持（如 HTTP 404）候选地址回退，以及完整回答的一次结构/质量修复。打开阅读和切换页签仍不发送 AI 请求。
- 接收总时长上限五分钟，空闲等待沿用现有请求超时设置；结束、失败和超时都会关闭本次客户端。

这是传输和完整性修复，不能保证外部网络永不断线。错误界面明确保留原分析，提供手动恢复路径。
