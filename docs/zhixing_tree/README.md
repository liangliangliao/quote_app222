# 知行树子系统

“知行树”已经作为独立 Flutter 子系统集成到“发现之旅”。目标不是增加一个普通待办，而是把“知道但没有做到”的问题路由为一个安全、现实、可验证的下一步行动。

## 用户闭环

1. 表达当前唯一的知行问题，并多选相关价值。
2. 回答六个诊断问题：自主、清晰、断点、不适、经验、行动阶段。
3. 本地安全路由先行，随后按需使用全局 AI 精炼。
4. 生成一张知行卡：主导思想、执行工具、制衡思想、触发、第一身体动作、完成证据。
5. 用户开始、卡住时调整、完成或选择无惩罚校准。
6. 记录三组轻量反馈：预测与实际、匹配与尺度、事实与下一步。
7. 结算经验、金币与树木资源，更新动态画像和思想有效性历史。

## 产品能力

- 十类挑战：恢复、定向、启动、突破、增强、持续、校准、止损、协同、生成。
- 四级难度：L1 微行动、L2 标准、L3 挑战、L4 转型；本版不会自动硬推高风险 L4。
- 三层思想匹配：主导思想、执行工具、制衡思想，附来源类型、置信度与误用边界。
- 离线可用：AI 未配置、超时或 JSON 不合格时，完整回退至本地引擎。
- 本地安全拦截：危机、暴力、严重状态和专业风险不会进入普通行动挑战。
- “我卡住了”：缩小、顺势、带着它做、重新判断。
- 无惩罚原则：未完成不扣币、不降级、不补签；失败进入反馈和校准。
- 健康游戏化：每日经验/金币上限、复归奖励、无排行榜、无金币充值。
- 树木生命周期：健康、缺水、枯萎、休眠保护、留下种子与保留历史的重生。
- 数据权利：逐条删除行动证据，或双重确认清空整个子系统。

## 本地数据表

所有表都在首次进入模块时通过 `CREATE TABLE IF NOT EXISTS` 幂等创建，不修改现有数据库版本：

- `zhixing_diagnoses`
- `zhixing_actions`
- `zhixing_evidence`
- `zhixing_match_history`
- `zhixing_state`

复杂结构保存在 JSON 载荷中；索引字段单独保存，便于状态与时间查询。

## AI 约束

AI 只精炼本地安全基线，不能改变本地确定的风险、安全路由、挑战类型、难度与奖励：

- 一次只输出一个主要现实行动。
- 必须包含触发、第一身体动作和完成证据。
- 不伪造思想家引语，不把综合方案伪装成原话。
- 不进行人格或临床诊断。
- 不把情绪消失当作行动资格，也不要求忍受现实伤害。
- 信息不足时保留本地基线，不编造用户经历。

## 验证

自动测试覆盖：

- 求职拒绝恐惧进入分级突破；
- 过劳进入恢复型且奖励水资源；
- 非自主目标先定向而不是优化执行；
- 危机语言绕过普通挑战且不做游戏化奖励；
- 知行卡 JSON 往返；
- 诊断与行动证据对动态画像的校准。

建议手工验收：

1. 从“发现之旅”进入“知行树”。
2. 完成六问并在 AI 已配置、未配置两种情况下生成卡片。
3. 分别测试开始、四种卡住策略、完成、未完成校准。
4. 验证重复点击完成不会重复结算。
5. 验证每日上限、复归奖励、资源兑换和养护。
6. 验证休眠、长时间状态、重生、逐条删除和全部清空。
7. 输入危机、医疗、法律和现实危险文本，确认安全路由优先。
