# 成为自己 · Self OS V3.7

依据《Self_OS_V3.7_完整产品方案.pdf》重新设计发现之旅内的独立产品。开发基线为 `main` 的 `805577cf2e0a82a023e0135704439df24aba928a`，分支为 `codex/self-os-v37-redesign`。

入口仍为 **发现之旅 → 成为自己 · Self OS**。首页保留「面临选择」「刚刚行动」「逐渐认识自己」三个入口；新案例首先进入「一起理清这件事」。五个分析工作台与五个引擎通过「分析与记录」按需展开，历史复盘继续可用。

## 核心体验改进

输入「想换工作，又怕后悔」时，选择入口保持在选择探索，不再因「后悔」关键词被误送到事后复盘。

1. 先从原始问题独立生成 5–10 个欲求候选，后台保留；引导结合具体处境，每次只问一个能影响下一步的问题。用户可以用自己的话回答、使用候选回答或纠正理解。
2. 引导回应最新补充，逐字引用原话依据，呈现想接近与想保护的价值。引用不存在的内容、忽略最新纠正、一次提出多个问题或首次直接安排实验的结果不采用。
3. 形成新角度时，对照原先理解与新解释，说明理由和未知，并提供收益、代价与未知对称的路径比较。用户认可后才保存 K/M/Att 前后变化、双向动机、路径和待验证问题；不会自动填入动机强度、概率或核实状态。
4. 根据这份理解安排一个小实验。默认展示动作、预期、观察方式与边界，可展开修改；用户填写触发时机，确认成本与可逆性。现场提示需单独认可，主观概率可保留未知。明确约定未来时刻时，实验也关联到 V3.7 的准备记录和事前快照。
5. 实验封存标记为 `commitmentScope: experiment`，与人生承诺分开。它不会降低大选择的风险、赋予主线许可或把仍未解决的未知判为充分。普通决定的 PASS 额外要求确认具体理解和剩余未知，零缺口记录不再等于充分认识。
6. 在现场使用原有冻结协议与单条提示，保留拒绝、暂停与新信息重审。实际反馈只需要记录完成情况、结果、情境与新认识；随后直接看到「当时以为 / 实际看到 / 带走的认识」。一次反馈不会自动证明因果、解决缺口或推断稳定性格。
7. 对话、未发送内容、纠正状态、计划和复盘草稿均可保存后继续。写入按顺序执行，失败不推进阶段；取消后不采用迟到分析；从详细分析返回时重新读取，读取失败时阻止旧草稿覆盖新记录。

这些改动是 V3.7 的体验入口调整，不替换其深度分析能力。50–100 个动机的完整搜索、因果地平线、敏感性、力量、Path Guard 和详细归因仍可按需要使用。引导中的路径后果只是推断候选，复杂高风险决定仍须进入证据与路径分析，不能靠一次聊天取得主线许可。

## 深度分析能力

1. 从真实欲求开始，保留 Why Tree 与独立 AI 假设两种视角。在选择空间比较结构不同的路径，分别记录一般价值与六项个人适配。
2. 确认本次成本、可逆性与机会成本。认识工作台检查遗漏，区分应询问自己的私有事实、应读取核验的公共材料，以及只能通过现实实验了解的问题。
3. 查看条件化因果图：近景、中景、远景；点击节点检查来源、反证、阈值、可逆窗口和下一阶。未来路径变化可带回选择空间继续比较。
4. 开始认识更新时保存 K/M/Att 基线。新认识形成后调整真实动机，再保存 K2 与动机变化之间的关系；如果没有改变决定，明确记录原因并停止重复准备。
5. 在冲突与决意中比较正反方，安排注意前景；在力量实验室用实际复盘验证力量、使用分寸和桥接动作。只有明确的未来时刻 T* 才安排最小必要的认识准备。
6. 通过认识门槛后确认行动协议。现场只展示一条已认可的观念或力量提示，保持 10–20 秒后连接第一动作；允许拒绝提示、退出或因新信息重审。倒计时不会代替实际行动反馈。
7. 行动之镜保存真实结果、K3、决意过程、提示作用与力量使用反馈，回写准备记录。比较 K/M/Att/E/T/Skill，再积累跨案例、跨情境的稳定模式候选。

## 数据兼容与边界

- 业务代码全部在 `lib/self_os/`；发现页入口已在 V3.0 中建立，本次不修改其他产品页面、公共 AI 服务、应用依赖或业务数据库。
- 继续使用 `self_os_v3.db` 的两张表与 SQLite 版本 1，JSON 文档版本升级为 2。兼容读取旧版本 1；旧复盘、协议快照和 ID 保留。新工作台单独带版本 37。数据损坏或未知版本明确报错，不清空重建。
- 重复确认协议时保留上一份封存协议；当前草稿修改不回写历史。主线切换和取舍记录原子保存，复盘与力量反馈也在同一事务保存。
- AI 使用现有 `UnifiedAiService` 与用户已有配置。候选须审阅采用；校验字段、数量、引用和图关系，禁止写入已核实状态、实际结果、主线承诺和用户预测。失败保留草稿，支持手动完成。
- 引导会自动请求现有 AI 配置；没有新增模型供应商或密钥。缺少配置或请求失败时保留输入，可重试或进入详细分析手动继续。新增引导状态是案例 JSON 的可选字段（版本 1），继续兼容没有该字段的旧案例，不改变数据库表。
- 外部资料通过用户提供的 HTTPS 链接读取，并由用户对照来源、摘录和时效完成核验；没有接入自动网络搜索引擎。模型不会声称已经搜索或核验网页。网页正文限定 1 MiB，显示最多 24000 字符，重定向与超时有边界。
- 认识准备时点保存在案例内并在产品中展示，不注册系统后台通知。数据本机保存，可导出；没有新增云同步、账号或后台任务。
- 冲突重要度 60、注意占据 35 等均为可解释的产品提示阈值，不是心理诊断。力量至少 3 条支持、2 个案例、2 种情境且支持多于反证才显示多情境支持；问卷、自评、重复引用及不存在的来源不增加可信度。
- 稳定变化候选还要求逐项核对 K/M/Att/E/T/Skill 与替代解释。未知不当作不变；没有把结果改善或内容阅读量换算成性格变化概率或因果成功率。

## 专项验证

仅运行以下 Self OS 范围，不运行其他模块或全仓测试：

```sh
flutter analyze --no-pub lib/self_os test/self_os
flutter test --no-pub test/self_os --reporter expanded
```

此前深度工作台有 68 项专项测试；本轮增加引导场景、纠正与保存恢复、实验与主线隔离、真实反馈关联、零缺口门槛等专项验证。最终数量以本轮 GitHub Actions 的 Self OS 测试步骤为准。

覆盖七类 GMRC 回归及六个领域的措辞/顺序不变性、风险门槛、核实/过期/冲突证据、敏感性、四类冲突、James 冷却、动机差异与封存快照、条件分支/闭环/剪枝/未来路径、T* 准备与行动回写、力量与归因门槛、旧版本数据库升级、全局主线事务、AI 权限与伪造引用、HTTPS 原文、五个工作台、手机窄屏大字体、图层交互、现场计时暂停和拒绝提示。

真实模型生成效果未在此环境请求验证；AI 测试采用可控响应与失败注入。引导场景从首页输入「想换工作，又怕后悔」开始，经过追问、认可解释、确认小行动，再保存部分完成的真实反馈；另覆盖纠正、保存失败、迟到响应、数据库关闭重开以及 320 像素宽屏的 1.6 倍字体。手机界面使用中文字体渲染检查，APK 由 GitHub Actions 编译。实际问答质量仍需在用户已配置的模型上试用验收。

## GitHub Actions 与 APK

选择源码工作流 **Build Android APK**：`.github/workflows/android_build_source_repo.yml`。仓库另有读取历史 ZIP 的同名流程，不能用于本次交付。

```sh
gh workflow run android_build_source_repo.yml \
  --repo liangliangliao/quote_app222 \
  --ref codex/self-os-v37-redesign \
  --field self_os_checks=true
```

运行名称包含 **Self OS V3.7**。此选项只执行本模块分析和测试，再以完整应用入口编译 release APK。成功后下载 **Artifacts → quote_app-apk**，解压得到 `app-release.apk`。提交使用 `[skip ci]` 避免无关推送/PR 测试，手动构建不受影响。
