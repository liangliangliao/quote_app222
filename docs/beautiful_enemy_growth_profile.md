# 美丽的敌人：关爱、事实与成长档案

基于 GitHub `main` 的 `37a34004fe3450efdc28f59a4f651477ab97ca9e` 实现。

## 本次调整

原实现以反对党、讽刺、激将与输赢为中心，最高档允许粗口，部分本地台词把沉默或缺少记录解释为逃避，完成后自动抬高要求。现在 AI 共用人设和离线台词遵循：对人保持关爱，对事实保持诚实，对成长保持要求。

共用人设明确美丽（理解、尊重、支持）与敌人（诚实、质疑、责任）两个特征，并覆盖事实监督、认知挑战、成长推动、动机唤醒、行动督促、反馈复盘、支持守护七项职责。七项职责被标为用户整合的实践模型，不冒充 Tal 原著的原文。

缺少记录不等于没做，沉默不等于认同；失败不否定人格，成功不自动加码。所有强度均禁止粗口。拒绝行动建议不要求理由，AI 可提出待验证的异议，但尊重选择。AI 反馈中的行动先保存为待接受建议；用户接受后才成为开放承诺，未接受的建议不会到期算作失约，也不进入履约统计。旧版自动生成、尚未接受且仍开放的判词行动在进场时调整为待接受建议。

## 使用方式

1. 打开「美丽的敌人 → 成长档案 → 上传弱点文件」，选择 TXT、Word（DOC/DOCX）或 PDF。
2. 核对可编辑的本机提取结果。可以按段落整理候选条目，移除非弱点内容，再确认每项弱点及希望改变的具体行为。目标、优势与可用支持可一并记录。
3. 点击「确认保存并用于后续活动」。也可以手动填写。每份档案最多 20 项弱点；上传新文件会替换当前档案，并保留既有承诺和历史行动。
4. 为一个弱点制定行动，写清最小行为、截止时间、遇阻预案和验证证据，亲自选择后保存。
5. 在档案中核对对应弱点与目标、标记完成，并记录实际结果及下次调整。行动同时出现在「字据」，沿用已有到期管理。
6. 可以查看原文、编辑、停用或删除。停用后新请求不再附带档案上下文；删除会移除原文、弱点和关联复盘，已选择的独立承诺、已有对话保留。模块的全量清空也清除档案和关联行动。

## 数据与调用

- 原文件在本机读取，不发送到文件上传 API。原文保留在本机 SQLite，只有用户确认的弱点、目标、优势、改变理由及关联行动进入 AI 上下文。用户在保存前可看到该说明。
- APP 沿用设置中的统一 AI 服务与已有调用接口；没有新增 API 密钥要求。
- `EnemyEngine.snapshot()` 在每次生成摘要时读取档案。对话、反馈、即时插话、主动巡查与后台任务共用此入口，避免后台使用过期的页面缓存。
- 档案明确标为可修正的用户自述，不加入 `evidence_ids`，单凭弱点文件不能生成对行为的判定；文档中的指令不作为系统指令执行。
- 行动的完成和复盘是用户自述，不声称已由系统独立验证。验证证据是用户约定的标准；本次没有增加自动截图或外部核验。
- 删除或编辑不会追溯删除既有对话中的文字，已经发出的 AI 请求也不能撤回。
- `be_growth_action` 与承诺、创建事件在一个 SQLite 事务中保存；档案保存在独立的 `be_setting` 项。v4 建表幂等兼容已有数据库。

## 文件支持与限制

- 单文件最多 12 MB、正文最多 60000 字，超过限制明确拒绝，不静默截断。
- TXT 支持 UTF-8、带 BOM 的 UTF-16 LE/BE、GBK。
- DOCX 读取 Word 正文段落、表格段落、制表符与换行，不把文档属性当正文。
- DOC 支持 Word 97–2003 的 OLE 容器、普通流/小流和 piece table 正文。更旧版本、加密或损坏文档提示另存为 DOCX，不扫描二进制的可读片段来猜正文。
- PDF 使用 `read_pdf_text` 的 Android PDFBox / iOS PDFKit 本机提取，以正确处理中文字体映射；扫描件需要先识别文字，加密文件需要先解密。此 PDF 原生通道支持 Android/iOS。
- 本次环境没有 Android/iOS 设备；PDF 原生通道通过 MethodChannel 契约测试验证调用和临时文件清理，发布前仍需真机核对中文 PDF 与系统文件选择器。
