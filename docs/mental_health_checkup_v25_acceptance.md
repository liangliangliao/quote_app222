## 结论口径

本文件区分三种状态，避免把“代码已实现”误报为“产品已发布”：

- **工程已实现**：需求已有可执行代码和对应自动化检查。
- **待设备验收**：代码已实现，但必须在目标 Android 设备上执行验收矩阵。
- **外部门禁**：需要课程专家、安全/隐私审核、正式签名或商店发布，不能由代码提交替代。

在 GitHub Actions 的测试、静态分析和 Release APK 构建全部通过前，不得把本分支称为“构建完成”。在目标设备、课程专家和发布门禁完成前，不得称为“可直接上架的最终产品”。

## 自动化门禁

专用工作流 `.github/workflows/mental_health_checkup_ci.yml` 必须完成：

1. 16 个种子文件的 SHA-256 与记录数测试。
2. 安全阻断、低覆盖、K/A/B、处方上限、复验调整、备份篡改和趋势测试。
3. 心理健康体检目录的 `flutter analyze --fatal-infos --fatal-warnings`。
4. Android SDK 36 Release APK 构建。
5. APK SHA-256 生成并随 Artifact 上传。
6. Artifact 使用压缩等级 6；不再使用导致下载包异常膨胀的等级 0。

构建环境应通过 `-PBAIDU_MAPS_API_KEY=...` 或同名环境变量注入宿主
地图 SDK 的 Android AK；Manifest 不再新增或复制明文凭据。未配置时，
心理健康体检的离线闭环不受影响，但宿主百度地图能力不能作为已验收功能。

## 集成宿主的明确偏差

V2.5 原始验收矩阵要求 Release Manifest 不含 `INTERNET`，且不申请位置、相机、麦克风等权限。当前目标是集成到既有综合 App；宿主的影视、定位、语音、相机和在线 AI 等既有功能已经声明这些权限。因此：

- 心理健康体检的**默认核心闭环不发起网络请求**，但整包 Manifest 不能被宣称为“无 INTERNET 权限”。
- 心理健康模块没有新增位置、联系人、麦克风、相机或全盘存储权限，但整包已有这些宿主权限。
- 现有 App 使用 `sqflite` 作为统一事实源，本模块沿用同一数据库并建立独立规范表，而不是另引 Room/DataStore。事务、外键、迁移、FTS 和数据生命周期要求已实现，但技术选型与参考骨架不同。
- V2.5 没有内置端侧生成模型。结构化本地规则报告始终可用；用户也可以在单次明确同意后调用宿主中由自己配置的 AI 提供方。若验收要求只能保留“端侧模型接口”，发布前应关闭这一宿主可选入口。

如发布门禁必须逐字满足 ADR-003、ADR-004、ADR-005 和 ADR-031，需要另建“心理健康离线独立构建/产品变体”，并对宿主其他页面进行裁剪或禁用；不能在不破坏既有功能的情况下从当前综合 APK 直接移除这些权限。

## 仍需完成的产品发布门禁

以下事项不能仅靠本仓库代码自动签发：

- GitHub Actions 首次通过后，在至少一台 API 26、API 33 和 API 36 真机执行完整飞行模式闭环。
- 执行错误密码、密文篡改、导入中断、磁盘满、进程杀死、重启和跨时区测试。
- 使用 TalkBack 和系统最大字体完成 B20、报告、课程行动和复验。
- 记录 2253 条首次导入和连续 20 次检索的目标设备性能阈值。
- 对 Release APK 做密钥、日志、合并 Manifest、自动备份和数据安全表审计。
- 由课程专家签发当前标记为“待课程专家确认”的证据关系和课程机制。
- 对92道历史题、46项历史任务以及新生成候选逐项完成独立证据审核、认知访谈和小样本试测；代码不会伪造这些外部结果。
- 配置正式、非调试的 Release 签名；完成隐私说明、Google Play 数据安全表和上架审核。
