# 名言整理省用量与分类结构统计 v6

基于 PR #205。上一版逐条请求，且队列会自动重试；每次还重复发送完整类别身份和主题/解读提示。遇到格式错误或网络失败时，可能继续消耗调用额度。

## 新的整理方式

“一键分批整理旧记录”默认本地优先：先复用相同原句的有效 AI 结果，再按原主题/已有类别别名建立本地初分。可唯一定位的下位类别会复用，不新建同名根类别；有多个同名类别时不任意选定。初分明确保留为 provisional，并不冒充 AI 的精细语义判断。

需要更深入的语义层级时点击“AI 批量细分”，只处理尚未进行 AI 整理的记录，保护人工归类。一次请求最多8条原句；同一批中的相同原句只发送一次。类别使用 c0/c1 等短 ID，每批共享紧凑词典；不再重复发送原解读、主题提示和作者头像路径。输出仅含分类、短摘依据及必要关系，保留逐句证据校验。

默认每轮最多3次请求，可选1/3/6次；每轮另有48000的保守预留用量估算上限。估算按 UTF-8 字节、输出上限及固定开销计算，不是模型实际 Token 用量或费用承诺。达到任一上限后暂停，须明确点击整理/重试才开始新一轮。重复点击、重开页面、重启进程不会补充尚未用完的额度；并发工作器共享持久化额度及发送锁。

**失败重试**：每条名言首次发送失败后，最多再重试3次（最多4次发送），间隔至少15/30/60秒；成功项保留，只重试失败项。每次都计入本轮预算，因此可能先因预算达到上限而暂停。可选择6次上限，为同一批保留完整的3次追加重试空间。重试计数持久化，达到上限不再自动发送；手动重试是用户明确开始新的尝试。模型返回的“需复核”是已完成但不确定的判断，不触发自动重试。

分类调用将输出上限限制在当前紧凑批次的额度内，全局较大的输出设置不会放大它。关闭分类请求的底层 HTTP 自动重试，由上述持久化队列控制；不会叠加“全局重试×队列重试”。其他业务的全局调用设置保持原规则。

相同原句的缓存记录依赖所用类别及其上位类别的名称、定义和层级。无关新增类别不使缓存失效，相关定义或层级变化会失效。原句编辑、删除、人工调整及过期请求仍按现有身份校验隔离。若进程中断时请求可能已发送，或从旧版迁移时无法确认原请求的计费结果，或请求超时/连接中断无法确认是否已计费，则暂停该项并提示人工重试，避免猜测性重发。这类结果不明确的请求不进行自动追加重试。

单批原句最多2200字符，提示最多10000 UTF-8 字节；超过限制保留原文并提示人工分类，不截断后冒充完整理解。自动生成类别最多6个，自动归类每句1至2类，必要关系最多2条。分类本身仍是可复核的主题索引，树图不构成概念外延包含的哲学证明。

## 统计与图形

“概念分类结构”读取本地分类库，不调用 AI：

- 总层数：根类别为第1层，取有效树中最大层数。
- 根类别：没有上位类别的类别。
- 父类别：具有至少一个直接子类的类别，可以位于任何层。
- 子类别：具有有效上位类别的类别。
- 叶类别：没有直接子类的类别。

“层级分布”用条形图展示每一层的类别数，点击可查看该层类别。“父子结构图”可展开层级，显示每个父类的直属子类数及全部下位类数；深层分支可单独进入，并返回上位类别。可切换仅统计已收录名言的类别；默认包括空类别，避免把尚未收录名言的已有类别漏掉。类别数量与收录名言数分别统计，孤立或循环的异常上位关系会单独标明。

## 验证

使用真实 SQLite 和模拟 AI 验证：33条已有主题记录零 AI 调用；8条不同原句只发送1个请求；重复原句去重及缓存；预算跨工作器持久化；最多3次追加重试；部分成功不重发；未知计费结果不自动重发；原文证据不串句；类别变更使相关缓存失效；HTTP实测本地测试服务器验证输出上限与单次传输；多层、空类别、异常层级及大字体界面。

预览由实际 Flutter 组件生成，测试分类数据及 AI 响应为可重复样例。实际节约比例取决于已有分类、本地可匹配记录、失败情况和供应商计费，不能仅按请求次数推定 Token 或费用下降比例。
