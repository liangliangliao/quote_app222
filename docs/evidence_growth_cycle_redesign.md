# 六模块完整循环改造（PRD v1.0 / KB35 v3.5）

## 产品理解与实现策略

依据：PRD §1/3/15–17/25–28（物理 p5/14/18/19），KB35 p62/145/158/194。
用户的真实问题是贯穿线索，Reality Trial 仍是执行单位。六模块形成
信念→目标→行动→失败/成功反馈→复盘→改变→新信念→下一轮现实的循环；
可从任何卡点介入，不能把这条链变成六张必填表或六个任务完成徽章。

前台保持四阶段：说问题、确认并做一步、记录实际、确认学习与下一轮。
AI 负责识别卡点、选择有依据的机制、提出可执行动作及下一轮调整。
用户确认目标、候选判断、预测与必要安全条件，实际行动并提供现实记录。
AI 推断不能冒充用户事实，个人样本不能改写公共知识库。

| 闭环职责 | 这次改造 | 验收重点 |
|---|---|---|
| 信念→目标→行动 | 每轮保存用户确认的目标、当前事实、关键差距、候选信念、观察信号及行动理由 | 明确这一步为何服务于这个目标；未知信念可以留空 |
| 行动→失败/成功 | 原预测不改写；未开始/中止作为启动障碍，允许立即调整 | 没做不等于能力反证；已行动不等于目标成功 |
| 反馈→复盘 | AI 接收本轮计划和限定长度的同问题历史，提出有范围的新判断、进展、差距与改变 | 只收到事实也可获得候选判断，不必先由用户做专家分类 |
| 复盘→改变 | AI 草案与用户确认版本分别存储，用户可纠正判断、目标、变化位置和下一行动 | 未确认的新判断不能被继承为用户结论 |
| 改变→下一轮 | ADJUST 重新检索和选择模块、节点、算子；ACT 保留已确认实验条件并重新核对 | 新反馈可使启动问题转为失败/完美主义或恢复问题 |
| 新一轮→新证据 | 新预测、新知识快照，原轮保持原样；明确父子链、根与轮次 | 可重启后继续；不能重复分叉、跨问题混合或复活 EXIT |
| 用户价值表达 | 本轮循环卡、完整问题历史、主页待继续学习、历史页下一轮入口 | 看得见现实如何改变后续行动，不把复盘保存当成行动完成 |

## 数据与兼容

在已有 operator_inputs_json 中存储带明确命名的 cycle_plan_json、
cycle_update_json（草案）、cycle_confirmed_json（用户确认）、cycle_root、
cycle_parent、cycle_round。复用现有保存、同步与个人数据删除机制；无需破坏旧表。
旧轮没有循环计划时不伪造旧信念；下一轮在用户确认时建立新计划。
改变检验命题后建立新的 hypothesis_id，避免把不同命题的负面结果合并触发退出。
同一问题的历史沿数据库明确的 next_trial_id 连接，不按同一个知识节点猜测。
AI 只接收最近六轮相关历史，完整本地链路仍可浏览。

ACT 原样保留有效实验条件；ADJUST 针对确认的一个变量，允许更换机制。
未获得足够信息时显示澄清入口；模型不可用时保留规则建议和手动确认，不能声称已完成智能诊断。
退出保存学习，关闭该路线；其他方向需要重新明确目标，不自动延续已关闭假设。

## 相关验证与限制

新增定向用例覆盖：跨轮换模块、确认前后信念隔离、新命题身份、原预测不变、
父子链恢复与防重复、未行动即时调整、退出不可复活、AI 使用真实反馈与旧学习、
无需人工标签的反馈解释、虚构事实不能支持 ACT，以及循环卡的待办状态表达。
只运行 evidence_growth 相关测试和分析、独立 API 分析及 APK 编译。
验证结果以 PR 对应提交 CI 为准，不以旧版本的通过结果代替本次验证。

自动化验证不代表用户真实 AI 服务的输出质量或真机体验已经验收；需要使用该构建
完成实际问题至少两轮，检查第二轮的知识选择和动作是否确实使用了第一轮反馈。
本改造不修改通知调度与无关模块；原有连续提醒仍承担返回本轮现实反馈的入口。
