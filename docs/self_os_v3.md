# 成为自己 · Self OS V3.0

依据《Self_OS_V3.0_完整产品方案.pdf》（21 页）集成的独立 Flutter 产品模块。

入口：**发现之旅 → 成为自己 · Self OS**。基线为远端默认分支 `main` 的 `ec8f7749fc2801e97e38da459dabccdda11657a2`，开发分支 `codex/self-os-v3-discovery`。没有合入其他未完成的专项或验证分支。

## 使用闭环

1. 在「此刻」输入现实选择，或直接记录刚刚发生的行动。下一步建议根据欲求确认、四类阻塞、双时态落差和历史执行情况分流。
2. 在五个引擎间切换；切换、返回和「保存」都会保存草稿。可以全程手动填写；点击 AI 按钮才请求现有的全局 AI 服务。
3. 确认行动协议时保存事前快照，包含认识、动机、欲求、预测和条件。必须有触发条件、第一动作、双时态预测以及正反动机。
4. 行动后记录情境、结果和至少一条新认识。未执行和部分执行同样可以产生证据；每轮只允许一条正式复盘。
5. 在「逐渐认识自己」查看校准数据、冲突矩阵、个人指纹和说明书，从证据提炼可修订的决策原则。开启下一轮时，K3 成为新的 K1，旧快照保持不变。
6. 在「人生路线」选择当前主线、次要保留、延期、低成本实验或主动舍弃。切换主线必须记录依据和舍弃项；路线与取舍记录在同一事务中保存。

## 数据与隔离

- 新增代码均在 `lib/self_os/`。现有文件只修改 `lib/pages/discover_page.dart` 三行：导入与独立入口及间距。
- 独立 SQLite 文件 `self_os_v3.db`，版本 1，`cases` 与 `profile` 两张表；不迁移、不读写其他业务模块的表，不添加依赖。
- 案例文档保留当前草稿、Why Tree、假设、候选、当前协议、逐轮复盘与快照。复盘 id 去重；损坏或未知版本数据会明确报错，不静默替换成空历史。
- 个人数据保存在本机。可主动导出本模块的明文 JSON 记录；不会导出全局 API 配置。尚未实现导入、跨设备同步或系统提醒，这些不是本次闭环的依赖。
- 统一 AI 服务复用应用现有的服务商、模型、请求参数和凭据。没有创建新密钥，没有写入凭据；没有修改公共 AI 服务。请求仅包含当前模块的相关材料与有限条数的历史摘要。

## 可解释规则与边界

- 候选置信度、适配度、行动概率是明确标记的估计，不包装为已训练的科学预测模型。
- 计划与现场差值至少 25 个百分点，或最近三轮至少两次高计划意愿（≥70%）未执行时，提示优先设计现场。这是透明的产品阈值。
- 个人动机历史反馈达到 3 次后，按用户自报的实际影响比例排序；不足时参考候选估计。保留正反动机，不把自报影响比例宣称为因果效应。
- 重复模式必须有至少 3 条用户确认「可归纳」的行动证据，跨 2 种情境、2 个案例；外部限制较强或尚不确定的记录仍保留在案例层，不自动进入性格归纳。
- 不适误差为事前预测减实际观察；行动概率校准使用 P2（若存在）或现场预测，完成为 100、未行动为 0，部分执行与缺失预测不混入二元误差。
- 未确认协议的事后补录不生成任何事前预测数据。下一轮重置预测，避免沿用旧轮次的数值。
- AI 建议只能落在白名单字段，不能写入真实结果、修改概率或生成已确认的事实。用户逐项采用；替换已有内容须在产品内确认。失败保持已有数据，停止等待后不再启动后续动机批次。

## 验证范围

仅运行 `test/self_os/` 和本模块的静态分析；没有运行其他模块测试、全仓测试或 APK / 全应用构建。

本次结果：29 项专项测试全部通过；上述范围的静态分析无问题。另使用中文字体与 Material 图标渲染了 390×844 的首页，检查实际显示。

```sh
flutter analyze --no-pub lib/self_os test/self_os
flutter test --no-pub test/self_os --reporter expanded
```

验证使用 Flutter 3.35.7 / Dart 3.9.2，与项目 3.35 系列兼容。Linux SQLite 测试需要可加载的 `libsqlite3.so`；本环境仅有 `.so.0`，通过仓库外的本地动态库链接提供给测试进程。

测试覆盖：四类分流、历史现场失败升级、预测缺失、正反动机约束、快照不可追溯改写、每轮复盘唯一性、K3→K1、Why Tree 合并回退、证据模式门槛、冲突矩阵、个人指纹、概率校准、SQLite 重开持久化、原子路线取舍、损坏数据保护、AI 结构校验与取消后续批次、入口导航、案例创建、失败恢复、复盘闭环、窄屏与大字体。
