# AI Wakeup 与语音闹钟联动

源码基线：最新非主分支 `fix/schopenhauer-concept-graphs`，提交 `41e75582`。

## 使用

1. 打开语音闹钟，选择要修改的起床或睡觉模板。
2. 在 AI Wakeup 卡片填写私有站点 HTTPS 根地址、设备访问令牌和站点服务凭据。凭据只在手机 Android Keystore 加密存储，不写入闹钟排期、Flutter 配置数据库或源码；清除应用数据后需重新配置。
3. 点“保存并测试连接”。只有服务返回当天正式内容才显示连接成功；登录页、鉴权失败、演示模式、未生成及过期内容均提示连接未完成。
4. 打开“使用 AI Wakeup 今日提醒”，再点页面底部“保存设置”。开关按模板保存，并同步到该模式下已经排期的闹钟。关闭开关时，沿用原来的语音、音乐与对话模式。

开启后，响铃服务在后台请求 `GET /api/alarm/today`，以 Asia/Shanghai 判定日期。音乐和振动立即启动；网络总超时 5 秒。仅接受 `settings.demoMode=false`、`shouldRing=true`、日期一致且 `isDemo=false` 的内容，拒绝 synthetic 内容。读取失败时使用原闹钟内容；不缓存云端正文。重启后尚未解锁时，私有凭据不可读取，同样使用原闹钟兜底。

请求使用 `Authorization: Bearer <设备令牌>` 与 `OAI-Sites-Authorization: Bearer <站点服务凭据>`。站点继续保持私有；本次代码不创建或修改站点令牌、模式、权限或定时任务。需要从本人合法授权的站点连接配置取得凭据，不应在聊天或日志中粘贴凭据。更换站点地址时不会自动沿用旧地址的令牌。

云端返回正文通过 Android 系统中文 TTS 播报，按引擎输入上限分段保持全文，长文播报期间不被周期复读打断。需在手机安装可用的中文语音引擎。原闹钟文件及现有对话 TTS 提供商配置保留；本次联动不调用付费大模型 API。

## 音量和关闭

- 模板中的“语音音量”和“背景音乐音量”独立保存；语音增益覆盖原文件播报、系统 TTS、AI Wakeup 正文及 AI 对话回复。
- 全屏闹钟页提供两个滑块，松手后应用于本次播放；系统 TTS 正在播报时从该条正文开头重新播报，以应用新的逐条音量参数。未来闹钟的默认音量仍由模板页面保存。
- 手机音量键调整当前输出使用的系统音量：扬声器对应闹钟音量，耳机对应媒体音量。应用不再自动拉高或恢复系统音量，因此用户设为静音时会保持静音。
- 讯飞新生成语音不再把播放音量烘焙进文件。更新前已生成的低音量或静音文件需重新生成一次。
- “关闭闹钟”、停止按钮、通知关闭及 Flutter 停止入口统一清除响铃状态，停止播放与识别并立即退出全屏任务；迟到的 AI Wakeup、AI 回复及 TTS 初始化结果不能重新播放或恢复全屏页。

## 验证

使用虚构内容和虚构凭据，不对真实个人正文或令牌作测试。可重复执行：

```bash
bash tool/voice_alarm_regression.sh
bash tool/voice_alarm_wakeup_regression.sh
```

第一组覆盖原有语音命令、回声与播放生命周期的 15 个场景；第二组覆盖北京时间、原文保留、正式模式、过期/测试内容、双鉴权头、HTTP 错误、登录页、超大响应、头注入、网络失败、迟到结果及长文 Unicode 分段等 16 个场景。回归不等于真机音量、语音识别准确率或实际响铃验收。

真机复验：关闭开关测试原模式；开启后测试当天正式正文及断网回退；分别将两个滑块调至 0/50/100%，验证文件、系统播报和 AI 回复；测试扬声器及耳机音量键；在网络请求或播报期间说“关闭闹钟”，确认页面、通知、音乐和语音均退出，等待十秒不重现。最后测试锁屏定时触发和重启解锁前兜底。
