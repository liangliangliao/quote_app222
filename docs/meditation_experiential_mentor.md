# 以用户主题为中心的 AI 冥想导师

此前生成已有八阶段结构，但校验主要匹配“身体、情绪、允许”等词。长段说理可以通过；默认状态和推荐还会影响用户选择的主题。逐句语音到时间点后会停止上一段，即使仍在讲话，也没有把说完后的体验停顿当成进入下一段的条件。整段语音模式会串读整篇内容。

## 这次的行为

- 用户原话决定主题，推荐和历史只调节节奏。短主题也能生成练习；标题/分析字段提到主题不代表正文已经回应。用户给出明确主题时，旧睡眠推荐不能把它改成助眠练习。
- 先设计一个体验过程：具体感官线索、可选择的身体动作、情绪允许和尝试后的觉察。正常模式使用贴合主题的温和画面，再接回真实身体；“真实感官”模式或中等安全分流不进入想象任务。
- 听者通过“邀请 → 留白 → 留意实际反应”练习。长段、概念讲解占主导、只在分析字段列感官、强迫感觉变化或没有停顿的稿件需要重写一次；仍不合格不交付。允许没有画面、没有感觉、没有变化。
- 原始 JSON 有 `experience_design` 和每段的 `pause_after_seconds`。设计字段不朗读。时长预算包括估算播报与体验留白；时间轴冲突会按体验阶段重新安排，保留可行的原时间轴。1–2 分钟保留短停顿，较长练习给核心体验更多空间。
- AI 逐句播放在下一段和结束边界等待当前声音与留白。实际语速较慢时，练习时间可略延长；睡眠定时器和手动停止继续生效。系统朗读等待真实完成；切换后的旧完成回调不会释放新段，原生引擎只回报错误时也能退出等待。
- 点击开始 AI 练习就进入导师逐句语音，不再依赖原来默认关闭的逐句开关。“播放导师引导”也使用当前 TTS 服务商按短段准备/播放，准备期间暂停计时，避免整篇连续朗读抹掉留白；缓存准备失败则使用系统朗读继续。不改写全局语音偏好，普通本地练习保留原播放模式。
- 页面优先显示体验邀请与开始按钮，认知解释和生活演练说明折叠。增加“温和画面 / 真实感官”选择。

## “允许自己为人”的示意片段

这是帮助审核体验设计的片段，不是程序给所有主题套用的固定脚本。

> 这次，我们试着把“允许自己为人”留给身体。先留意脚底与地面的接触。不需要坐出一个正确的样子。
>
> **安静停留。**
>
> 如果愿意，想象一束柔和的光落在手边。留意光的明暗，也留意此刻手掌真实的温度。画面不清楚时，只感受触感也可以。
>
> **安静停留。**
>
> 试着让手掌少用一点力。这几秒钟，先不修正一个轻微的不完美。你不需要先变得完美，才可以停留在这里。
>
> **安静停留。**
>
> 留意这个小尝试之后，胸口、手掌或情绪有没有反应。仍然紧张、没有明显变化，都可以。我们只是给真实的反应留一点地方。

实际脚本由用户已有的模型和配置生成，内容会随输入和感官选择变化，未固定到上述比喻。

## 验证范围

自动化使用受控模型响应验证生成请求、主题优先级、正文体验门、一次重写、拒绝不合格内容、一分钟练习、真实感官模式、阶段顺序、播报时间预算和等待留白。模拟平台通道验证系统朗读会等待完成，以及引擎错误不会无限等待。测试不会读取或调用真实供应商密钥。新增 Meditation Mentor CI，整包 release 编译由 Build Android APK 执行。

这些检查验证的是生成和播放约束，不能证明任一供应商每次都能产出优秀引导，或每个人都会体验到变化。真人试听与供应商语速仍需在用户设备上确认。旧的已保存脚本不自动改写，使用新逻辑需要重新生成一次。
