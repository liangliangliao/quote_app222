# 以用户主题为中心的 AI 冥想导师

此前生成已有八阶段结构，但校验主要匹配“身体、情绪、允许”等词。长段说理可以通过；默认状态和推荐还会影响用户选择的主题。逐句语音到时间点后会停止上一段，即使仍在讲话，也没有把说完后的体验停顿当成进入下一段的条件。整段语音模式会串读整篇内容。

## 这次的行为

- 用户原话决定主题，推荐和历史只调节节奏。短主题也能生成练习；标题/分析字段提到主题不代表正文已经回应。用户给出明确主题时，旧睡眠推荐不能把它改成助眠练习。
- 先设计一个体验过程：具体感官线索、可选择的身体动作、情绪允许和尝试后的觉察。正常模式使用贴合主题的温和画面，再接回真实身体；“真实感官”模式或中等安全分流不进入想象任务。
- 听者通过“邀请 → 留白 → 留意实际反应”练习。可恢复的长段先按自然标点拆成短段，缺失停顿在本地补齐。概念讲解占主导、正文缺少实际感官或身体觉察、强迫感觉变化或阶段缺失时需要重写一次；仍不合格则说明具体原因。允许没有画面、没有感觉、没有变化。
- 原始 JSON 有 `experience_design` 和每段的 `pause_after_seconds`。设计字段不朗读。时长预算包括估算播报与体验留白；时间轴冲突会按体验阶段重新安排，保留可行的原时间轴。1–2 分钟保留短停顿，较长练习给核心体验更多空间。
- AI 逐句播放在下一段和结束边界等待当前声音与留白。实际语速较慢时，练习时间可略延长；睡眠定时器和手动停止继续生效。系统朗读等待真实完成；切换后的旧完成回调不会释放新段，原生引擎只回报错误时也能退出等待。
- 点击开始 AI 练习就进入导师逐句语音，不再依赖原来默认关闭的逐句开关。“播放导师引导”也使用当前 TTS 服务商按短段准备/播放，准备期间暂停计时，避免整篇连续朗读抹掉留白；缓存准备失败则使用系统朗读继续。不改写全局语音偏好，普通本地练习保留原播放模式。
- 页面优先显示体验邀请与开始按钮，认知解释和生活演练说明折叠。增加“温和画面 / 真实感官”选择。

## 返回内容已有，但页面提示失败

初版优化把推荐段数、字数范围、最后一段的位置、主题逐字复述和辅助设计字段一起作为硬性校验。八分钟的完整八阶段稿件也可能被整份丢弃；“不保证放松”又被关键词规则误判为效果承诺。所有这些失败只返回 `null`，页面显示配置、网络或质量的笼统提示，而全局日志只显示模型请求已经成功。

现在先恢复可确定的格式和播放信息，再检查内容：

- 识别普通 JSON、围栏中的 JSON 和被编码为 JSON 字符串的正文，逐层解码；不盲目替换转义符。日志中的 `\\n`、`\\"` 本身不代表解析出错，普通 API 响应中的正文字符串也会以转义形式显示。
- 保留原文及阶段顺序，按句末标点拆短段；必要时在逗号处断句。无法自然拆开的超长文字继续交给模型修复，不删掉正文来凑时长。
- 兼容数字或字符串秒数，缺失/无效的体验停顿补为可播放留白，辅助的 `intent`、练习标签与缺失时间轴在本地恢复。所选时长保留为目标，完整版本的实际排程由正文和必要留白共同决定；两者不同会明确显示。
- 推荐段数、字数和结束位置不再单独阻断完整稿件。主题允许用设计中的具体表达自然转述，短主题锚点允许摘取两字词语；实际正文仍需要回应主题并有感官、身体与情绪体验。否定承诺和“不需要在脑海中想象”不会被当作结果宣告或想象任务。
- 使用明确的配置、空响应、格式、内容、请求失败分类。页面用自然语言显示内容原因；全局“错误异常”日志保留全部校验详情。自动修复超时也保留原响应和原问题。
- 可用练习立即显示“开始专家引导”。可选的推荐说明在后台补充，慢响应或失败不影响开始练习；诊断保存失败也不吞掉可用内容。

## 有效引导预计超出目标时长

此前“569 秒超过目标 480 秒”被当作内容错误。一次自动重写仍超时，整份已经返回的引导便被拒绝；自然断句又可能给每个新片段补一个完整体验停顿，进一步增加时间。

- 生成请求明确预算正文和留白，建议播报占约 70%、体验留白占约 30%，提示模型先估算再填写时间轴。这个比例是创作建议，不作为新的内容拒绝规则。
- 原段落拆成短句时，中间片段使用短停顿，段末保留原体验任务的停顿，不把格式拆分变成多个完整任务。
- 先在本地按可调整容量缩短停顿，保持相对节奏。3 分钟起，核心身体、情绪、允许与场景体验优先保留 8 秒，其余保留 4 秒；原有有效的更短停顿不强行加长。1–2 分钟保留至少 1 秒。正文、阶段顺序、结束收束和语音速度都不因此改变。
- 若仍放不进目标，完整版本使用足以容纳所有播报和停顿的时间轴。页面显示“目标8分钟 · 预计9分29秒”，提供“开始完整引导（9分29秒）”和“重新生成8分钟版”。用户通过有时长标注的开始按钮选择较长版本，目标滑块不自动改变。
- 校准后超出的秒数大于 `min(120, max(15, floor(目标秒数 × 20%)))`，最多再请求一次精简。原本内容合格时，只有更短且仍合格的版本会替换原稿；精简请求超时、格式错误、丢失体验设计或未变短，都保留原完整版本供选择。内容不合格仍按原质量规则拒绝。
- 保存的完整版本保留预计秒数、完整时间轴与原目标说明；练习库显示分钟及秒数。诊断记录包含原估计、目标、最终排程、停顿调整和精简结果。播放器继续等待真实语音完成及体验留白，实际语速可能使练习略延长。

## 从主题理解到连续体验

只有八阶段、感官词和身体动作，仍可能写出适用于任何主题的通用引导。现在先用 App 已有的模型和 API 配置生成简短体验设计，再据此写正文。设计包含用户原话、可能的内在冲突、旧反应想保护的需要、一个可检验的认知区分，以及同一主题下的微小体验。没有透露的经历不当作事实；推测用“如果贴近你”表达，用户明确的否定和边界优先。

- 核心过程是：辨认原有规则或冲动 → 观察身体和情绪的原状 → 理解可能的保护需要 → 尝试一个可撤回的小变化 → 留白 → 观察实际反应 → 回到认知区分和日常选择。画面承担主题任务，并有真实感官替代，不只是装饰。
- 例如“允许自己为人”可以尝试让一处轻微的未完成暂时存在，观察想纠正它的冲动、身体用力和不安，再辨认“承担责任”与“承认此刻有限”能否并存。“害怕被拒绝”则围绕普通请求、等待与想提前解释的冲动；悲伤主题不被改写为必须释怀或变积极。
- 没变化、抗拒、麻木或更紧都允许如实存在。引导不宣布用户已经放松、释怀，也不由一次身体体验推断生活中永远安全。1–2 分钟只做一个小对照，较长练习在同一主线上展开，不靠增加议题和字数制造深度。
- 正文的 `depth_evidence` 摘录五处真实文字供编辑核对：原有反应、试验、情绪接触、体验后的理解、日常延续。检查引用出现在对应阶段，且理解在试验后的段落；正常断句拆开的相邻片段仍能匹配。它只是编辑线索，不是语义质量评分，也不证明用户一定有深入体验。
- 设计无效或请求失败时继续生成正文。深度建议与原有内容/时长修复共用最多一次校对；深度附注缺失不会成为新的硬性拒绝条件。有效原稿不会因校对超时、候选稿损坏或仅改善附注却增加预计时长而消失。通常为“设计 + 正文”两次请求，需要校对时最多三次；相比原来可能增加等待和模型用量。页面显示当前生成阶段。
- 原有配置、正文质量门和完整时长选择继续生效。辅助设计只接受已知字段、完整结构及来自用户原话的锚点，不使用默认推荐替换用户主题。生成日志记录设计、编辑建议、候选采用情况，供后续排查；这些附注不朗读。

## “允许自己为人”的示意片段

这是帮助审核体验设计的片段，不是程序给所有主题套用的固定脚本。

> 如果贴近你，轻轻听一听这句话：“只有先把事情做好，我才可以停一下。”它也许熟悉，也可能与你无关。
>
> 先不改变什么。留意听到它时，手指有没有用力，身体是否想赶快行动；情绪可能不安，也可能没有明显感觉。
>
> **安静停留。**
>
> 那份想做好的心，也许在保护认真或被认可的需要。你不必赶走它。如果连停一下都有些不安，给这份不安一点位置；这并不要求你同意每一个催促自己的判断。
>
> 如果愿意，把一个轻微的未完成放在纸面的一处空白里，留意纸上的光影。没有画面时，就看看眼前的明暗，感受座面的触感。
>
> 只在这一轮呼气里，试着暂不补齐那一处。手指可以少用一点力，座面仍在这里；“允许自己为人”，能否先成为这一刻的小尝试？
>
> **安静停留。**
>
> 等一等，再留意手指和身体用力。情绪有没有不同，或还是原样？如果更紧，就放下场景，睁眼看周围一个物体，也可以暂停。
>
> **安静停留。**
>
> 回看开头那条规则：这一小刻的支撑，是否非得等事情全做对才有？你注意到了什么，就先保留什么；没有变化或答案，也不用替自己下结论。

实际脚本由用户已有的模型和配置生成，内容会随输入和感官选择变化，未固定到上述比喻。

## 验证范围

自动化使用受控模型响应验证生成请求、主题优先级、正文体验门、一次重写、拒绝不合格内容、一分钟练习、八分钟八阶段变体、JSON 包装、自然转述、否定表达、阶段顺序、播报时间预算和等待留白。569 秒与 480 秒回归分别验证可校准停顿和必须保留完整版本；同时覆盖精简成功、超时与丢失内容。手机尺寸的 Widget 测试验证预计时长、完整版本选择、按原目标重新生成和保存时间轴，以及附加说明失败不吞掉结果，真实内容失败会说明原因。SQLite 集成测试验证内容错误能在全局日志筛选中找到，并保留原响应；模拟平台通道验证系统朗读会等待完成，以及引擎错误不会无限等待。测试不会读取或调用真实供应商密钥。Meditation Mentor CI 执行这些检查，整包 release 编译由 Build Android APK 执行。

用户截图没有包含完整的 `segments`；“认知转变”与 569 秒回归样例采用受控正文和时长，不把构造样例当成设备原始响应的完整回放。

深度生成回归覆盖设计传入正文、原话与否定边界、不同主题、设计缺失/串题/超时、包装解析、虚构或跨阶段引用、认知整合先于试验、自动拆段，以及校对失败和候选变长时保留原稿。示例正文为人工编写的测试材料，不代表线上供应商本次实际生成的内容。此次本地及 Meditation Mentor CI 仅检查冥想模块；APK 工作流编译整包，其他模块的可选测试保持关闭。

这些检查验证的是生成和播放约束，不能证明任一供应商每次都能产出优秀引导，或每个人都会体验到变化。真人试听与供应商语速仍需在用户设备上确认。旧的已保存脚本不自动改写，使用新逻辑需要重新生成一次。
