# 以用户主题为中心的 AI 冥想导师

## 一次生成，保留已返回的引导

用户输入“恐惧”后，AI 已返回引导，页面却显示“结束收束 缺少对应的可体验引导”。原规则用“睁、看见、周围、听见、回到、休息、入睡、环境”等少数词判断结尾；“感受脚底的支撑，轻轻活动手指，让视线慢慢清晰”也会被判失败。自动重写仍未命中时整篇被丢弃，反复消耗 token。

当前行为：

- 每次点击生成只发起一次 `meditation.daily_script` 业务调用。主题理解、体验设计和正文写作在同一次请求里完成，复用 App 当前模型、API、用户自定义提示和感官偏好。
- 移除独立设计、自动重写、自动精简和生成后的推荐说明调用。也不再要求 `depth_evidence` 重复摘录正文；系统写作要求不再重复塞入输入数据。底层网络重试仍遵循用户已有的 API 设置，不由冥想模块额外增加。
- 关键词、段数、阶段名/顺序、主题逐字复述、设计附注和内容风格等规则只记录 `content_advisories` 诊断建议，不触发失败、红字或模型重写。诊断自身失败也不能影响正文交付。写作质量仍由生成提示引导，建议不冒充语义评分。
- 用户明确点击“重生成”或“重新生成目标分钟版”才会发起新的生成请求。成功结果可以保存到本地重复使用，不需要再次生成。

## 返回内容的本地处理

- 普通 JSON、围栏 JSON、双重编码 JSON 沿用原有解码。可读的纯文字、文字围栏、JSON 正文字段，以及由字符串组成的段落也可接收。
- 按原顺序保留所有可读正文。缺少 `phase`、`intent`、标题、时间轴和停顿时使用本地播放默认值；未知阶段名不拒绝正文。不按建议段数截断文章，不因为缺少“结尾关键词”补写、覆盖或丢掉 AI 的原文。
- 空白或非文字段落记录为格式修正，保留其余可读段落。超过建议长度时按自然标点拆成短段，完整正文保持。
- 空响应、无法解码的损坏结构、只有元数据而没有正文、HTML 网关错误仍不能直接朗读。原始返回保留在日志中，页面明确说明未自动重写，由用户选择是否重新生成。不会把损坏 JSON 本身读给用户听，也不会伪造一篇脚本掩盖失败。
- 有正文的输出日志记录成功、原始响应、格式修正、内容建议和实际排程；不能播放时才记录失败。普通生成前的现实安全分流继续保留。

## 主题认知与体验转化

用户原话决定整篇主线，推荐和历史只调节方法。当前 `topic_to_experience_v2` 要求可播报正文讲清主题是什么、为什么重要或可能让人卡住、可以怎样尝试，再用对应的画面关系、用户参与动作和身体/情绪观察落实这份理解，最后回看认知并延续到生活。认知解释不能只藏在折叠说明或设计附注，也不能被通用呼吸与许可替代。

画面可以是温和象征或可进入的想象空间，不限于普通风景；它的物件、关系与行动应表达同一个关键区分。例如“允许为人”可通过为感受卡片留位置，探索感受尚在与不急着按感受行动能否并存。参与后分别观察真实身体和情绪，再回看允许与服从的区别。真实感官模式用实际触点与动作承载同一个理解；用户边界、睡前和低刺激偏好继续优先。

完整方法、可复制提示词和完整人工参考稿见 [主题与体验模板](meditation_mentor_pattern.md)。简短的 `conceptual_understanding` 与 `imagery_bridge` 只辅助审阅，不作为返回内容的校验门槛。所有理解与写作仍在一次请求内完成，不增加自动评审或重写。

## 时长与播放

- 时长预算包括估算播报和体验留白。先本地调整可缩短的停顿；核心体验保留必要停留，不加速或截断正文。
- 仍超出目标时直接显示目标与完整版本预计时长，例如“目标8分钟 · 预计9分29秒”，由用户选择开始完整版本或手动重新生成。无论超出多少，都不自动请求精简。
- 自然断句后的中间片段使用短停顿，原任务的段末停顿保留；保存完整时间轴和预计时长。
- 下一段和练习结束继续等待当前语音真实完成及体验停顿。系统朗读、语音回调隔离、手动停止和睡眠定时器沿用已有行为。

## 验证范围

测试仅在 `test/meditation` 内执行，静态分析仅检查冥想模块及其测试。覆盖自然收束的页面展示与保存、缺少阶段/设计附注、单次请求数量、无自动推荐说明、纯文字和混合格式、长文保留、真实格式错误、原响应日志、手动重新生成、时长校准，以及语音完成与留白。

测试使用受控模型响应和人工编写的正文，不调用真实供应商，也不把这些检查当作引导深度或个人体验效果的保证。APK 工作流负责整包编译，其他模块的可选测试保持关闭。旧的已保存脚本不自动改写；安装新版后重新生成即可使用新逻辑。
