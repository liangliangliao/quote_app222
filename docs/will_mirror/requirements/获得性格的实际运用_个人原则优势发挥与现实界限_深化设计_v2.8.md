# 《意志之镜》v2.8 专项深化设计

## 获得性格的实际运用：个人原则 × 优势发挥 × 现实界限 × 决策反馈

**设计状态：** Flutter Android / FastAPI PRD深化设计，所有接口和验收均为拟开发内容，不意味着程序或模型调用已实现。  
**基线：** 完整继承《意志之镜》v2.7、唯一 `Case`、既有 T1—T326、§4B.1—§4B.20。  
**新增主PRD：** §4B.21；**新测试** T327—T366（40项）；**优先级** P0可核验原则闭环与现实辨析，P1优势发展/人际期待体验。  
**哲学来源：** 叔本华《作为意志和表象的世界》第四篇§55关于获得性格：通过经验认识个人所欲/所能/界限，将这种认识提升为明确的一般原则，并在未来情境运用；认识必然性与不幸的事后接受。其形而上学前提不是现代测量事实。

## A. 产品命题与理论边界

v2.7 已能提出 `WantHypothesis`、`CharacterInsightRevision`、`FunctionalFitAssessment`、`MotiveRecommendationRun` 和不同路线评分，但“认识”常只停留在事后文本。v2.8 的唯一新核心是 **`有来源的经验洞见 → 可撤回个人原则 → T0情境匹配 → T1真实调用 → T2应用与结果证据 → 原则版本修订`**。不增加性格问卷、独立仪式主菜单、自动自律警察或命运接受页面。

必须区分：①**睿智性格**是叔本华超时间的形而上学说法，不能被观测/测量；②**经验行为与能力表现**可以收集经过许可的事实证据；③**获得性格**在本软件中仅指可修订、条件化的个人经验认识；④**个人原则**是用户可认可/修改/拒绝的行动启发式，不是永恒天性、法律规范或强制命令。不存在“原则违反一次=本性堕落”“能力弱=人不值得”“过去无法改变=未来不值得干预”的推断。

需求目标：减少每次遇到类似课题都从零开始、减少外界榜样对不适配目标的误导、在临场认知受限时提供简短可执行的经验提示、让既有能力与现实机会相互匹配、减少无效反事实反刍。不可声称提升一定成功、消灭后悔、训练无限可塑，不能把受害者顺从定义为心理成长。

## B. 四个功能切片与准确分工

| 功能切片 | P0/P1 | 源头复用 | 新增的可观察成果 | 不得发生 |
|---|---|---|---|---|
| 个人原则生成与应用 | P0 | CharacterInsightRevision、WantHypothesis、ActionPatternHypothesis、Case | 条件性原则候选、用户认可、T0/T1/T2证据 | 用大模型发人格判词；凭一次成功确证永久原则 |
| 已知优势的机会匹配 | P0轻量 / P1完整 | TaskRequirement、CapabilityConditionEvidence、FunctionalFitAssessment、RouteFit | 真实任务中有依据的优势使用建议、支持/训练/改道 | 由身体表征推断性格；当前差距判为不可训练 |
| 改变/接受/核实辨析 | P0 | ObstacleEvidence、CausalReview、OutcomeDeviationReview、SupportVariant | 事实时态、可改变性证据、可补救行动、未知 | 认为痛苦注定合理；劝受害者忍受伤害或放弃求助 |
| 他人期待与自主边界 | P1 | ChoiceOpportunity、ObstacleEvidence、Case、Route | 区分自己的行动、对方自主决定、义务与现实协商 | 从几次经历推断他人的本性永不改变；操纵/羞辱他人 |

**一条可操作原则的最低结构**：`做什么（可观察）＋何时触发（场景条件）＋为什么/来自何证据（出处）＋适用/不适用条件＋安全/他人权利门槛＋失效/反证条件＋用户自主状态＋下次检验`。例如“重要且易拖延的任务，在前晚准备真实所需资料并确认外部时间；出现新健康风险则暂停核实”，而不是“我必须永远变得自律”。

## C. 自我认识与原则的证据资格

1. 从已授权历史检索至少一组支持事实和主动搜索反例，区别直接自述、实做、他人证据、设备消息、纯想象与模型假设。**两次经历不一定独立，不能硬阈值视作心理定律**；只有单次时也能提供`tentative`候选，但不得称长期稳定原则。
2. 判断可比性：任务类型、影响动机、当前认识、健康及功能条件、资源、外界要求、他人参与、时间跨度等；不可比则保留分歧，不强行形成“统一的人生法则”。
3. LLM生成候选原则最多3条，默认仅显示最相关的1条；逐条附`evidenceIds`、`counterEvidenceIds`、`contextPredicate`、`riskGate`、`revisionTrigger`及具体 If–Then 版本；可以全部跳过。
4. 独立校验：每个事实ID是否真的存在且在允许的时间内可见；`knownAt`只用于当时认识，事后发现的理由不能写作当时想过；用户撤回证据后，原则自动失效/待复核。
5. 原则是否“成熟”由证据充分度与用户认可分开表达：`draft`、`user_accepted`、`needs_review`、`user_rejected`、`retired`；“用户认可”不等于“科学验证”。
6. 候选原则必须与可能的反向动机及可行路线兼容；对身体/制度/他人同意等硬约束不允许激励绕过。
7. 如果没有足够支持，则输出“尚未找到可复用的个人原则；可先尝试低风险方法”，而非用鸡汤补全。

**与Top5的关系**：v2.7 `MotiveRecommendationRun`可以引用被用户接受且适用的原则作为一条可审查**历史证据**，但不得把原则自身的分数再作为验证该原则的依据，否则形成循环自证；动机排名不证明原则正确，真正校准来自随后T1/T2观测和长期反馈。Top5始终保留重要反方/现实风险、允许低证据降级。

## D. 临场运用：三时点五状态

| 时点 | 用户能够看到 | 系统记录 | 不允许推断 |
|---|---|---|---|
| T0事前 | “过去这类场景中，哪些方法可能帮到你？”原则卡+事实+适用条件 | proposed / opened / accepted / declined / scheduled | 开过卡=用户已承诺/必将采用 |
| T1实际情境 | 用户亲选的短提示+新事实/风险核实+改道入口 | delivered / seen_unknown / explicitly_recalled / rejected / context_changed | 通知送达=看见；看见=理解；理解=真实应用 |
| T2事后 | 对照“建议—现场想起—具体采用—实际尝试—观察结果—新证据” | applied_verified / applied_self_report / not_applied / unknown，实际结果另记 | 结果好=原则必然造成；没行动=无价值/无欲求 |

**现实用例**：用户准备参加一次招聘：原则候选“提前核实真实岗位要求、准备资料与路线”；T1收到通知时岗位条件发生变化，应用原则不是机械去，而是重新核实并自主选择。T2实际未入职但已完成资料准备与岗位核实，不得清空已执行努力；更不能将临场合理退出定义为原则失败。

提示必须<=20秒可读可听、可完全关闭、可查看完整出处/反证。Android通知默认不包含敏感能力或心理文本，点击通过`caseId + principleId + triggerId`深链到节点；未授予通知权限保留工作台操作，离线用本地已授权缓存，重启/被系统杀后台后不保证绝对准时。

## E. 优势发挥：按任务匹配而不是人格分级

采用`CapabilityConditionEvidence`记录**具体任务、特定情境、可观察表现**，不生成统一“天赋排行榜”。分清：已实证优势 `demonstrated_strength`、训练改善 `trainable_gap`、有支持才适配 `fit_with_support`、暂时波动 `variable_state`、当前限制 `task_mismatch`、未知 `unknown`。这些都不是对人的终身标签。

匹配过程：解析任务实际要求并查来源 → 许可下关联用户已观察技能及用户自述 → 先评估安全及合法资格 → 提供使用优势的任务变体、辅助工具、可训练能力、环境修改、协作/替代路径 → 让用户以低成本试验验证，而不是宣判职业“命定不适合”。

默认不请求疾病、外貌、诊断或身体测量；仅在功能适配/安全确需时询问最低必要事实；隐私撤回后关联推荐变`stale`。不能推断他人或用户的道德价值、智力、人格和根本意志。

**情境例**：某人有多次可信的软件测试缺陷分析记录，可以提出“在需求分析与缺陷定位任务中优先尝试发挥已验证经验”；但不能据此认为其不适合艺术、销售、管理，也不能仅凭未做过某工作就评估为永久不胜任。利用优势的满意度和可持续性必须另行检验（§4B.18）。

## F. 现实可改变性与事后接纳的状态机

输入固定为 **某事实/障碍在某时点、某任务和某资源条件下是否可干预**；不能对整个人下“可改变/不可改变”的总标签。状态如下：

| 状态 | 判断资格 | 推荐方向 | 复核条件 |
|---|---|---|---|
| `irreversible_past` | 事实已发生、不能重演 | 接纳时间事实；寻找补救、责任与下一步 | 新证据纠正事实描述 |
| `modifiable_now` | 有证据支持当前可采取的行动 | 提出低风险操作及实施证据 | 新资源、风险、实施反馈 |
| `modifiable_with_support` | 需要训练、工具、协作、资源等 | 说明具体支持和同意成本 | 支持取得或失效 |
| `hard_limit_for_task` | 经核实的特定任务要求/安全限制 | 暂停此路线、替代路径、专业帮助 | 新工具/制度/身体条件变化 |
| `externally_dependent` | 对方自愿行为、制度批准、外界事件等 | 能做的沟通、申请、风险控制；尊重对方 | 现实回应/政策改变 |
| `uncertain` | 没有可靠证据判断 | 低成本核实、保留未知 | 用户更正/新证据 |

**抗“宿命接受”硬规则：** 只能对**已经发生的事实或有经验证据的特定任务限制**谈现实接受；不得从多次受阻推出“永远没希望”；不得对暴力、虐待、强迫、剥削、歧视或安全威胁提出顺从、认命或仅通过调整心态忍受的建议。需允许求助、保护、投诉、离开、法律渠道等适当选择。不可把“我不再抱怨”作为唯一积极结果，合理愤怒、悲伤和争取权利都允许。

**反事实痛苦处理**：T2将`事实已经怎样`与`我原来以为可以怎样`分离；若有现实补救/责任继续行动，若确实不可改变则提供可选择的情绪支持，不要求用户接受某种哲学解释。痛苦主观体验是真的，原因“本可避免”是否正确须依据当时时点的信息、资源和因果不确定性核实。接纳不是推卸责任。

## G. 第三方行为：合理期待而不是预测他人天性（P1）

当用户请求他人改变，模型划分：自己可控制的沟通/边界与行动；对方自愿选择；依法或契约约定的实际义务；制度性资源；安全风险。建议可包括明确事实、商议条件、一次合理表达、边界协商、保存必要证据、合法救济或退出不安全关系。不得生成对第三人不可逆的人格判决（“他就是永远不会变”）或操纵感化策略。禁止未经许可抓取私人聊天记录和跨Case使用他人敏感数据。

## H. 与历史架构的一一关系（不能造平行人格数据库）

| 数据对象 | 与原实体的复用/新角色 | 证据权限与版本 |
|---|---|---|
| `PersonalPrinciple`（新，P0） | `principleId, ownerId, summary, ifCondition, thenAction, exceptionRule, supportEvidenceIds, counterEvidenceIds, applicableContext, maturity, userStatus, sourceRevisionIds, safetyPolicyVersion, createdAt, version`；指向`WantHypothesis/CharacterInsightRevision/ActionPatternHypothesis` | 证据撤回自动失效并禁止缓存旧解释；用户可编辑/拒绝/归档 |
| `PrincipleApplication`（新，P0） | `applicationId, caseId, principleId, principleVersion, triggerId, exposureStatus, recallStatus, applicationStatus, actionAttemptIds, observationIds, atT0, atT1, atT2` | 不用一个布尔值混合展示/实际执行/结果 |
| `ChangeabilityAssessment`（原ObstacleEvidence/CausalReview补充，P0） | 特定`factId/obstacleId/routeId`的`timeReference, contextRequirements, classification, sourceEvidenceIds, reviewAt, safeAlternatives`；宜先作为现有结构的扩展JSON/派生视图，必要时才独立表 | 外部/内部混合解释、风险版本、未知并存 |
| `StrengthOpportunityMatch`（派生视图，P0/P1） | 只引用`CapabilityConditionEvidence/TaskRequirement/SupportVariant/RouteAssessment`，记录任务级机会与训练验证状态 | 不复制医疗/健康信息、不能永久存笼统天赋名次 |
| `InterpersonalBoundaryReview`（P1候选） | 在现有`ChoiceOpportunity/ObstacleEvidence`挂第三方自主/义务/风险/沟通选项 | 默认不同意共享第三方个人敏感数据 |

推荐关系 `PersonalPrinciple 1:N PrincipleApplication`；`PrincipleApplication N:1 Case`；`PersonalPrinciple N:M Evidence`由已有证据关联表实现；`CharacterInsightRevision`可先于Principle生成。原则修订生成新版本而非覆盖历史；T1/T2当时版本引用不可悄然改变。跨Case请求用显式许可快照；被撤回原事实后有关原则/推荐/画像标记`stale_due_to_revocation`。

## I. AI推理管线、可信校验与伪代码

```text
S0 restore_allowed_case_evidence(caseId, consentSnapshot)
S1 classify facts, user's prior words, observed acts, inferred motives, unknowns
S2 get CharacterInsightRevision + support/counterevidence (only in allowed scope)
S3 propose <=3 conditional PersonalPrinciple candidates; require evidenceIds
S4 validate knownAt timestamps, actual context, safety, changing circumstances
S5 show 0..1 default candidate; user may edit/accept/reject/skip
S6 if Case matches: generate brief application cue, preserving opposing motives
S7 T1 record delivered != seen != consciously_recalled != actually_applied
S8 T2 review execution, action and outcome as separate observable layers
S9 assess contradiction / condition mismatch / new evidence -> revise or retire
S10 Top5 receives eligible principle as bounded historical feature only;
    NEVER use recommendation score as evidence that principle is true
```

每个AI输出必须结构化，Schema校验允许`unknown`与空原则列表。评分排序服务不得把个人原则提升为无条件100分；反方风险优先审查，规则变化可解释。用户可以在导出、删除、停止远程评估、关闭提醒时维持基本离线功能。

## J. Flutter与API契约（建议，不是已部署）

**Flutter**：在原Case工作台加“我的经验原则”可折叠卡、来源抽屉、可编辑 If–Then、`采用/修改/不适用/稍后/跳过`操作；临场深链与工作台同源；获得性格页按`个人原则 / 实际适用 / 反例 / 尚待验证`聚合，但不添加主导航。优势机会卡仅在具有真实任务证据时显示；改变/接受卡先展示状态与核实来源，再给安全可行下一步，不使用红色羞辱标签。无障碍支持文字朗读、关闭动画和单色状态文本。

**建议FastAPI**：

```text
POST  /v1/cases/{caseId}/principles/suggest
GET   /v1/me/principles?status=active
PATCH /v1/me/principles/{principleId}
POST  /v1/cases/{caseId}/principles/{principleId}/apply-checkin
POST  /v1/cases/{caseId}/principles/{principleId}/review
POST  /v1/cases/{caseId}/constraints/changeability-assess
GET   /v1/cases/{caseId}/strength-opportunities
```

服务端按登录身份、Case所有权、最小授权与证据版本检查；对敏感数据实施字段级降敏及撤回传播；`PATCH`支持乐观锁版本，旧原则的当时应用不应被改写。Flutter/Drift使用带迁移的表、离线保存用户主动确认的原则与T1/T2状态；网络失败不生成虚假应用证据。密钥在服务端、远程LLM可禁用。规则风控先于评分调用。

## K. 端到端用户故事与异常场景

**故事A｜原则与真实行动分离。** AI从两次可比任务中发现“前夜核实材料更容易开始”，用户认可候选；第二天只收到通知未打开，系统保留`noticed=unknown`；最终没去，必须记录事前准备真实发生但原则现场运用未知；不能判“原则无效”。

**故事B｜规则发生反例。** 用户曾在安静环境下工作顺利，AI提出环境原则；后来在协作环境中也完成，旧规则不能强制约束“永远只在安静处工作”，标记反例并重估条件。

**故事C｜有技能差距但可训练。** 本次任务需要某项可训练能力，AI不得将“缺少当前证据”标记为天生缺陷。提出训练、小试或工具；若用户实际训练改善能力，则更新任务适配。

**故事D｜不可逆过去与可变未来共存。** 错过已截止的申请属于不可重写，但未来类似申请可以准备；AI允许情绪与补救，又提供下一次行动计划，不能以“命中注定”结束对话。

**故事E｜遭遇不公。** 单位强迫超范围工作时，AI不能用“必然性安慰”劝忍耐。应区分权利、健康安全和现实选择，允许合理求助或停止危险手段。

**故事F｜关系期待。** 对方拒绝并不证明“其本性永远如此”；系统将对方自主决定和自己的边界分开，允许合理沟通或退出，不提供操纵说服策略。

| T334 | 通知送达未打开 | delivered不升级seen/recalled/applied |
| T335 | 打开卡片却未行动 | viewed不升级applied；允许未知 |
| T336 | 实际准备发生却行动受阻 | 保存准备与受阻，不算零努力 |
| T337 | 行为完成但不清楚原则作用 | 结果与因果解释分离，不强断有效 |
| T338 | 多次反例出现 | 原则降级/归档并解释版本变化 |
| T339 | 撤回原证据 | 相关原则和推荐stale，敏感通知不继续引用 |
| T340 | 同一原则用于Top5排序 | 只能引用有证据的历史洞见，不以排序反证自己 |
| T341 | 排名第一动机不符合原则 | 必须保留合法反方与用户自主权 |
| T342 | 多条原则争执 | 给出冲突/适用条件，不能发相互矛盾的绝对命令 |
| T343 | 没有可靠经验 | 可以零原则而完整完成原Case |
| T344 | 功能/技能能力已有实证优势 | 推荐任务机会并给出处，非人格能力排行榜 |
| T345 | 某能力可训练但当前欠缺 | 不贴永久缺陷，允许训练/工具/复测 |
| T346 | 当前健康状态暂时不佳 | 不升级为稳定永久限制 |
| T347 | 任务有硬安全资格要求 | 不用优势分或Top5分覆盖闸门 |
| T348 | 新兴趣无历史经验 | 允许低风险探索，不用已有性格封锁 |
| T349 | 未授权身体/健康信息 | 不默认收集/传输，完整Case仍可用 |
| T350 | 过去事实已不可更改 | 区分接受事实与仍可做的责任补救 |
| T351 | 外部条件实际可改变 | 输出具体介入步骤，不以命定解释中止 |
| T352 | 某限制依赖辅助工具 | 支持变体及条件可行，不判永远不行 |
| T353 | 不确定是否能改变 | 标unknown及核实动作，不宣布不可能 |
| T354 | 暴力/胁迫/歧视情境 | 保护与求助优先，不劝顺从或认命 |
| T355 | 反事实后悔反复 | 分事实/推测/补救/未来行动，不作确定反事实 |
| T356 | 对方拒绝改变 | 尊重他人自主，不诊断对方永久本性 |
| T357 | 对方有契约/法定义务 | 允许事实核实、记录与适当合法渠道 |
| T358 | 用户经历悲伤愤怒 | 允许情绪存在，不要求“平静才算接受” |
| T359 | 用户违背旧原则一次 | 不羞辱、不贴道德/人格失败标签 |
| T360 | 多情境行动原则 | 保留生活多样性，不能只形成一种人格故事 |
| T361 | 低网络/关闭API | 离线展示已认可原则，不编造最新证据 |
| T362 | 关闭通知/撤销语音 | 核心工作台仍可使用，无惩罚 |
| T363 | 用户退出/删除资料 | 关联索引和派生缓存停止使用敏感数据 |
| T364 | 深链跳转 | 点击对应caseId+principleId+triggerId而非首页 |
| T365 | 时间版本错误 | T2新认识不得倒灌T0/T1，旧原则引用不被覆盖 |

## M. 落地阶段、测量与质量标准

**P0 最小可用**：在既有Case中选取1条有证据的候选原则，用户可认可/编辑/跳过；在真正相关的T1情境小负担重呈现；T2记录是否采用与现实结果；支持撤回、反证和可改变性判断；跨越原Top5/功能任务时保证安全闸门；完成T327—T366自动和人工核验。质量指标：证据回链率、适用条件错误率、已见/已应用误升级率、撤回传播时延、误判不可改变率、未来任务建议可执行性、用户自主退出有效性、跨版本回归通过率。

**P1**：增强能力优势匹配及支持训练试验、人际现实期待和实际生活适配反馈，并在获得性格页构建简洁的“有效原则—适用证据—更新轨迹”。**P2**：经用户同意做长期对照研究，评估原则提示是否改善有效的现实决策，不以情绪被打动、点击率或规则遵守率替代用户福祉，避免选择偏差与奖励操纵。

**不可宣称**：已开发APP、后端、数据库迁移、已经证明个人本性不可变、已临床验证技能或人格测量、已验证干预有效、AI预测未来必然决意。任何方法与哲学源头的关系应清楚标注“产品推导/待实验”，保留修改和删除的实际操作权。
