1. **基线/差距审计**：检查 `lib/pages/discover_page.dart` 里现有的 `WillMirrorDiscoverEntry -> WillMirrorHomePage`；核对 `lib/will_mirror` 代码、AI配置复用、Vault、KB、tests 和 workflow。建立 v2.8 每项 P0 需求的【已有/部分/缺失/实现文件/测试】矩阵；不得把“已有 V5”冒充“满足 v2.8”。
2. **P0 功能闭环**：现实课题输入及事实/信念/未知分离；基于证据的 `WantHypothesis`；50—70 条语义有效的正反动机候选（不足时如实说明、不可编造充数）；选取最值得审议的 5 条 Top5 动机；开放路线与欲求适配、风险与可行性独立闸门；事前审议 T0/未来条件等待/现场 T1 新事实核验/实际决意与尝试 T2/真实结果和后续 T3；多轮斗争、行动证据与因果复盘；个人原则和能力证据到新 Case 的复用及修订。
3. **OpenAI 协同**：复用宿主现有 AI Provider 配置，明确授权才上传最小必要信息；支持结构化输出校验。对 Decisions API 的实际开放状态、接口和模型能力先从官方最新文档核实，不得写一个未经验证就声称已调用的假接口。不可用时提供诚实的可解释本地降级，不得把本地打分标记成 Decisions API。用户 API key 永不进源码或日志。
4. **UI/UX**：遵照 PRD 在「发现之旅」独立入口内完成；默认一步输入与渐进呈现、关键 Top5 与正反理由、路线比较、现场提醒或可选触发、行动回访、人生轨迹、获得性格证据以及可用的个人原则。复杂知识与 50+ 理由隐藏在可展开视图，不强制问卷；给出实例自动填充与证据说明；中文可读性与辅助功能优先。
5. **数据安全**：保留现有独立加密 Vault/Keystore、KB 权限及既有数据；设计迁移/版本管理，明确数据删除、修改撤回、缓存失效、事前封存快照；敏感内容默认只存本地且锁屏提醒不展示。不得用“睿智性格”做诊断、测量，不能给不可改变的人格结论，不羞辱用户，不鼓励宿命论。
6. **验证与交付**：逐项落实适用的 T1—T366（文档中的部分项会需要专项验证记录）；新代码增加单元/Widget/数据持久化及安全回归测试。执行 `flutter analyze`、相关 `flutter test`、现有 GitHub Actions CI，尝试 Android APK 编译。实际报错必须修复或明列阻塞，不能声称未执行的测试已通过。提供提交、PR、测试结果、完成/未完成矩阵和可以复现的演示步骤。

### 关键不变量
- `Top5 动机`是**优先审议的理由**，不是 Top5 行动路线、真实意欲比例或行动成功概率；允许合理反方、少于5条、未知。
- `Route` 路径欲求适配 ≠ 身体技能适配 ≠ 外部可行性 ≠ 认知动机；生命/健康/法律/他人自主权硬闸门不可被高分覆盖。
- `计划` ≠ `临场决意` ≠ `真实尝试` ≠ `完成` ≠ `获得后满足`；通知投递 ≠ 看见 ≠ 受到影响；不把事后信息倒填进T0。
- 努力发生过不等于努力一定有效，最终成功不意味着此前所有失败是必要条件；没有行动也不证明缺乏真正欲求。
- 个人原则是有证据、反例、适用情境、版本和撤回的可检验推断，不是对用户本质的判决；优势与短板可以变化。
- 既有 WillMirror V4/V5、向己、知行树、发现页其他入口及其它业务不可破坏。
