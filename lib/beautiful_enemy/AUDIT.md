## 3. 未做的（诚实清单）

1. **语音闹钟承诺提取**：未接。`VoiceAlarmActivity` 是大型原生流程，改动风险高，没有把握不破坏现有的语音识别修复。目前承诺靠手动立下或由判词产生。
2. **闹钟行为、熬夜时长、App 使用时长**：没有采集。宿主没有现成的会话记录表，新增需要一个全局生命周期观察者，触碰 `main.dart` 的面更大。
3. **实时推送事件**：当前是拉取式。如果要做到各模块写入时即时推给敌人，需要在对应 DAO 里加一行 emit；建议在 CI 转绿后单独做。
4. **晨间 TTS 朗读**：未做。
5. **每周审判日的定时通知**：未做，只有页面内的本地统计。
6. **通知点击直达模块**：通知带了 payload，但没有改宿主的通知点击路由。

## 5. 隐私与数据流

- 全部数据只存本机 SQLite。
- 只有一份聚合摘要（≤ 约 2KB JSON）会发给已配置的模型服务：计数、状态、承诺文本、习惯名称、最近三条判词。**承诺文本和习惯名称是你自己写的字，会随摘要发出。**
- 模型不可用、超时或输出不合规，会降级成本地事实播报，不发送任何内容。
- 每个来源默认未授权，需要在判词页或设置里授权。

## 6. 已知风险

- 禁词表是第二道防线，不可能穷举；第一道是系统提示。如果模型绕过了，请用「太过了」按钮反馈，并把原文发给我，我来补规则。
- 安全阀基于关键词，会漏掉不用这些词的表达，也可能误触。它是兜底，不是诊断。
- 「停战」「太过了」「安全阀」的存在不代表这个工具适合在低谷期使用。状态不好的时候，请先联系身边可信的人，必要时联系专业人员。

## 7. v2：从「看板」到「对手」（体验层重做）

用户反馈 v1 像会计、不像敌人：只在点「开庭」时出一条判词，用词是案卷和判词，模型不可用时退成一行统计，没有对话，没有实时反应，没有声音。v2 针对这些重做了体验层，**判词、证据、护栏的内核不变**。

| 改动 | 说明 |
|---|---|
| 对峙页（替代「判词」页） | 判词、插话、对话在同一条时间线上。敌人先开口；你可以回话、反驳、被盘问 |
| 人设 | 判词和对话共用一份人设：克制、精准、有记性、从不先动怒；赢了认账，被驳倒了让步。本地台词也是同一个声音（`persona.dart`），模型不可用时不再退成统计 |
| 称呼 | 默认「对手」，可改；羞辱性称呼和过长的称呼会被拒绝（否则敌人就会这样叫你） |
| 实时插话 | 对峙页打开时每 30 秒、App 其它页面每 60 秒看一次；只对**新增**事件开口（习惯完成/未完成、火种完成/中途退出、知识卡转换、字据兑现/失效），按优先级挑最重要的一件。你刚做完动作时会立即接话 |
| 字据与赌注 | 承诺可带赌注（输了就做的一个行动）。到期输了，敌人当场把赌注摆出来；兑现了，赌注作废。赌注只能是行动：伤害自己、羞辱、涉及钱的都被拒绝（`StakeGuard`） |
| 快到期提醒 | 字据剩 10 分钟内提醒一次 |
| 出声 | 用宿主已有的 `flutter_tts`，语速放慢、音调压低。**默认关**，在设置里开 |
| 其它页面也插话 | App 开着但不在敌人页面时用通知插话。设置里可关 |
| 界面 | 修了按钮文字和开关滑块的暗紫色（跟随了默认主题的 onPrimary），改为白色 |

### 7.1 护栏（v2 新增的部分）

- 用户对敌人说的话先过安全阀：危机表达或「停战」时敌人立刻退场并静音 24 小时；**这句话不会被存储，也不会发给模型**。
- 模型说出的每一句话都要过 `validateLine`：长度、禁区词/句式、粗口只在 3 档。不合规重试一次，再不合规用本地台词。
- 插话有静默时段、每日上限（默认 6 条）、最小间隔（5 分钟）；静音对所有路径生效。`force` 只绕过间隔和上限，不绕过静音。
- 总开关「实时插话」和「在其它页面也插话」都在设置里。

### 7.2 默认值（请知晓）

- **「实时插话」和「在其它页面也插话」默认开**，因为这是你明确要的；不想要就在设置里关。
- 「出声」默认关。

### 7.3 仍然没做 / 做不到

1. **App 退到后台后实时开口**：Android 不允许后台常驻定时器，只有「每日报到通知」那一条定点通知。这里不假装能做到。
2. **起床闹钟后由它先开口**：未接。需要改 `VoiceAlarmActivity`，风险高。
3. **语音闹钟承诺提取、熬夜时长采集**：仍未做（见第 3 节）。
4. **点通知直达敌人页面**：通知带了 payload，但没改宿主的通知点击路由。
5. **模型回复的「事实核对」**：只靠人设提示和禁区校验，没有逐句对照证据核实数字。模型仍可能把事实说错；说错时请用「申辩」或「太过了」反馈。

## 8. v3：从「等你来」到「自己巡」（自主性重做）

用户要求：敌人要能随时发现用户在指定模块里的任何动静，主动跟踪、督促、评判，不能靠用户去唤醒它。v3 针对这一点改了感知、主动性和核对三块。

### 8.1 改了什么

| 改动 | 说明 |
|---|---|
| 3 秒感知 | 前台常驻（App 一启动就开始，不用打开敌人页面）。每 3 秒看一次；靠来源的**变更指纹**（几次 O(1) 查询）判断有没有变化，没变就不重读数据。之前是 30/60 秒 |
| 主动巡查 | 没人叫它、也没有新事件时，它自己判断该不该开口：早上的晨报、晚上的结算（默认 20 点）、人在 App 里待了 20 分钟以上而案卷没有新记录、且字据还开着时点名。一天一次/冷却 3 小时，受静音、静默时段、每日上限约束，设置里有「主动巡查」开关 |
| 后台巡查 | 登记一个 Workmanager 周期任务，App 不在前台时也每隔约 15 分钟巡一次，用通知开口。前台有心跳时让位，避免两边同时说 |
| 更多的眼睛 | 新增两个来源：**其它模块的动静**（24 张用户记录类表，只记录「哪个模块、何时有新记录」，**不读内容**；字据还开着、而你在别的模块忙，敌人会点出来）、**使用时长**（App 前台分钟数，只存计数） |
| 核对说法（找真相） | 你说「做完了」而账上没有记录 → 盘问；账上有 → 核对后认账；你说「没时间」而今天在 App 里待了 30 分钟以上 → 把数字摆给你看。只指出「账上有/没有」，不猜动机，不说你撒谎 |

### 8.2 默认值与存量迁移（请知晓）

- 「主动巡查」默认开。
- **新增的两个来源（其它模块的动静、使用时长）默认未授权**——包括已经授权过旧四个来源的存量安装。对峙页会出现一张卡片提示「还有 N 处我看不到」，点「全部授权」即可，也可以在设置里逐个开。
- 使用时长按天在设置表里存三个计数键（分钟数、深夜分钟数、首次打开时间），不做自动清理。

### 8.3 仍然做不到的（诚实清单）

1. **App 完全关闭/被系统杀掉后的秒级响应**：做不到。Android 不允许后台常驻定时器。后台只有约 15 分钟一次的巡查，最短间隔是系统规定的，省电策略（小米等厂商尤其严）可能推迟或杀掉任务。**要接近「随时陪在身边」，需要常驻前台服务（带一条常驻通知）**——这要新增原生服务、清单权限和依赖，我在无法编译验证的情况下不敢动整个 App 的构建，建议在 CI 转绿后单独做一个提交。
2. **「任何模块的任何动作」**：目前覆盖行为追踪、火种、知识卡、24 张记录类表的新增记录（按表名推断标签，可能不准）和 App 前台时长。**更新操作（改了旧记录）只有行为打卡和行为记录能感知**，其它表只看新增行。宿主有三百多张表，我没有逐个确认语义，新增来源只需在 `enemy_sources.dart` 里加一个类或往表清单里加一行。
3. **「真相」的边界**：敌人只能依据账本说话。账上没有的事，它只会说「账上没有」，不会断言你没做；模型仍可能把数字说错，错了请用「申辩」或「太过了」。
4. **页面内的发呆检查不做**：你在敌人页面里时它不会判你在别处发呆。
5. 仍未做：语音闹钟承诺提取、起床闹钟后由它先开口、点通知直达敌人页面。

### 8.4 护栏（v3 新增部分）

- 所有主动开口都过同一套校验和限频：静音、静默时段、每日上限（默认 6 条）、最小间隔（5 分钟）、各开关。
- 使用时长、其它模块的动静都需要单独授权；授权前不采集、不计时。
- 其它模块的动静只存「模块名 + 时间」，不读取任何记录的内容。
- 核对说法时只陈述账上有无，提示里明确要求「不要说他撒谎」「不评价他这个人」。

## 9. v4：为什么 v3 的效果「看不到」，以及怎么改

用户测试 v3 后反馈大部分改动没有看到实际效果。我没法在真机上复现，所以**没有声称找到了唯一原因**，而是核对了代码路径，找出了确实存在的缺陷和设计问题，并加了自检页让问题可见。

### 9.1 确认存在的缺陷

| 问题 | 影响 | 修法 |
|---|---|---|
| 后台周期任务在**首帧里**登记，而 `Workmanager.initialize` 在首帧**之后**才执行（`main.dart` 的启动流程里有明确的先后要求） | 登记可能失败或登记了却没有可调起的回调，后台巡查等于没有 | 登记挪到 `_bootstrapAfterFirstFrame` 里、`initialize` 之后；登记结果和失败原因写进设置，自检页显示 |
| 两次开口之间最短间隔 **5 分钟**，每日插话上限 **6 条** | 连续测试时，做第二件事要等几分钟才有回应，做到第 7 件事之后一整天不再开口，而且没有任何提示——很像「没生效」 | 间隔改为 20 秒，上限改为 30；主动巡查不再占事件插话的上限（否则上限用光后晚间结算也不会开口） |
| 对峙页的定时器要等第一次 `step()` 返回后才挂上；第一次 `step()` 可能要等 AI（最长 30 秒） | 页面刚打开的那段时间「不看」，加载一旦出错就永远不看 | 先挂定时器，再做加载和第一次检查 |

### 9.2 设计问题（不是 bug，但会让人以为没生效）

- **大量行为是有条件的**：晨报只在 7–12 点、晚间结算只在 20 点后、发呆要待满 20 分钟、使用时长和其它模块动静要先授权、一天一次、静默时段 23–7 点完全不开口。短时间测试几乎不可能同时满足，而之前没有任何地方告诉你「现在为什么没说话」。
- **新增的两个来源默认未授权**。「还有 N 处我看不到」只是一张卡片，容易错过。

### 9.3 新增：自检页和演练

新增「自检」标签页：

- **在线状态**：前台心跳、上一次看的时间和结论（刚开过口 / 没有新动静 / 已静音 / 静默时段 / 间隔没到 / 上限到了 / 开关关着 / 没有该主动说的事……）。对峙页顶部也会显示一行同样的状态。
- **看得到什么**：每个来源是否授权、案卷里有多少条、最近一条多久之前；事件游标。
- **主动行为的条件**：晨报/结算今天做过没有、发呆冷却、今日使用时长。
- **后台巡查**：任务是否登记（失败显示原因）、最近一次运行的时间和结论。
- **演练按钮**：晨报、晚间结算、发呆点名——不等条件，现在就用真实的案卷和字据把它走一遍，消息带「【演练】」，不占今日上限，也不会让今天真正的结算作废；还有「测试通知」。
- **验证后台通路**：「重新登记后台任务」和「10 秒后在后台跑一次」——后者通过 Workmanager 一次性任务在真正的后台调起，跑完会发一条「后台演练」通知并写下运行记录。点完回桌面等十几秒，再回来看「最近一次运行」：有时间说明通路通了；一直是「从未」说明被系统拦了（小米等机型的后台限制很常见）。

### 9.4 仍然不能保证的

- 我仍然**没有编译、没有运行**这些代码。如果自检页显示某个环节有问题，请把那一页的内容告诉我，我按它修。
- App 被系统杀掉后的秒级响应依然做不到（见 8.3）。后台通路通不通，要用自检页上的按钮验证，而不是我断言。
