# 照见（Zhaojian）模块审计

基线：`origin/codex/contextual-action-forecast-v3-20261008@641b0d17`（拉取时提交时间最新的分支；`main` 是它的祖先）。
功能清单与完成占比见 `PORTING.md`（由 `tools/porting.py` 从清单算出，不凭感觉）。

## 做了什么

web 原型（叔本华「性格 × 动机局面 → 决定 → 行为」因果链）移植为独立 Flutter 模块，接在「发现」页。
五组入口：**选择 / 行动 / 改变 / 我 / 方向**，共 25 个页面，首页只显示已注册的页面。

| 组 | 页面 |
|---|---|
| 选择 | 决策（六步：写选择、补全动机、体验卡、天平与冲突诊断、一致度与难度、封存预测）、信念检验（远期汇票） |
| 行动 | 未开的牌（现场速查、开牌、自知分、回放）、行为记录、知行（落差诊断、愿望漏斗、念头省察）、回望（悔恨诊断、手段检查） |
| 改变 | 改变引擎、计划与复盘、绳子、小墙与假设行动、接受、认知重构 |
| 我 | 自画像、证据（行为考古、他人观察、自述线索）、主线与假设、AI 分析、决策方式、变化、签名、原理 |
| 方向 | 目标链、一条线、探测、放弃拆分器、成长回顾 |

贯穿的机制：反宿命论护栏、绝望或自伤迹象即停下并转向求助、行为证据门槛、动态下一步与分散度提醒、
AI 引擎适配（JEV → AI 模拟 → 规则）、引擎预测的三方揭示、签名与决策联动。

## 决策引擎

宿主层 `lib/zhaojian_host/`，模块本体不碰网络和密钥：

- **打分**优先用真实的 **JEV（System One）**，复用「证据成长」里已启用、已配置的密钥；每个候选一个独立的 score 问题，每批 12 题。
  JEV 不可用（没启用、没密钥、限流、响应不合规、不足一半的候选有分数）→ 回落到通用大模型按决策引擎格式的**模拟**打分 → 再回落到规则推荐。
- **文字生成**（补全动机、AI 列选项、研判、改变方案、认知重构、AI 分析等）只走文字引擎（AI）；没有时每一处都有自己写的路径。
- **隐私**：凡是会把用户内容发给外部服务的操作，点击前都披露发给谁（`ZhaojianOracle.sendsData` / `generateLabel`）。
- 一致度与难度、AI 分析等目前只走文字引擎，**没有接 JEV**（需要 choice 题型与更复杂的回落）。
- 「AI 引擎预测」存起来、开牌前不给用户看，避免影响用户自己的判断。

## 数据

全部在本机 SQLite，表均为 `z_` 前缀，无外键：`z_meta`（版本与键值，键值键名加 `kv:` 前缀）、`z_decision`、`z_log`、`z_hyp`、`z_miss`、`z_item`。
`z_item` 是通用条目表，按 `kind` 区分十几类条目（绳子、小墙、计划、行为考古、签名……），新增一类条目不需要新表。

模块自管 schema 版本：v1 → v2 新增 `z_decision.align_json`；v3 新增 `z_item`。宿主库 35 → 36（建表）→ 37（v2）→ 38（v3）。
`migrate` 先幂等补表，再按模块记录的版本补列，已有数据保留（有测试覆盖）。

## 集成契约（与火种一致）

- `lib/zhaojian/`：除 `flutter`、`sqflite` 外零外部依赖；不自己开库，不引用 `AppDatabase`。
- `lib/zhaojian_host/`：等库、注入引擎（JEV → AI 模拟 → 规则推荐）。
- `lib/data/db.dart`：onCreate 调 `ZhaojianSchema.createAll`，onUpgrade 调 `ZhaojianSchema.migrate`（均幂等）。
- `lib/pages/discover_page.dart`：入口卡片与 `_openZhaojianFromDiscover`。

## 红线与边界

不做诊断；不依据外貌、体型判断性格；身体信号只是线索；分数只是排序和对照的依据，不是结论；筹码是虚拟的，没有随机奖励；
假设行动四条红线、放弃实验两条红线；AI 分析里命中诊断、外貌、宿命式措辞的条目被丢弃而不是改写；
「自由感」统计只说明行为对自己可预测，不证明决定论。
詹姆斯五种决策、勒温/米勒冲突的措辞据二手资料整理，上线前请核对原文。

## 没做的（如实）

- **一致度的敏感性检验**（逐个关掉外部条件看结论是否翻转）：只做了「换欲求看排序是否翻转」。
- **Choice/Score/Noul 式研判**：原型里是三种题型的研判；这里只有叙述式研判。
- 一致度、AI 分析、手段检查没有接真实 JEV，只有 AI 或自评。
- OpenAI Decisions API 没有接入（格式相同，可再写一个 `ZhaojianOracle` 实现，需要新的密钥设置入口）。
- 数据只能导出（复制 JSON），不能导入。

## 验证状态（如实）

- **编译**：整个 app 的 Flutter release 编译在 CI 里通过（`Build Android APK`，Flutter 3.35.3，不是备用的 Gradle 路径）。
  中途有过一次失败：第一批里有重复声明（控制器里两个 `exportJson`、`ZCopy` 里两个 `threeLayers`），已修。
- **数据库**：Kindling CI 和 Zhixing Tree CI 里的「打开宿主库」测试在 schema v3 下通过，说明建表在真实打开流程里没问题。
- **测试**：`test/zhaojian/` 写了 6 个文件、约 106 个用例（纯函数与阈值、schema 迁移、DAO 往返、控制器流程、AI 输出解析与降级、JEV 请求结构与回落、导航注册表、入口卡片），
  但**没有在 CI 里跑过**：专属工作流 `zhaojian_ci.yml` 没能推送（令牌没有 workflow 权限），需要手动加进 `.github/workflows/`。
  我也没有本地 Dart 环境，所以测试的断言是对着代码手算核对的，不是运行过的。
- 静态自查（本地脚本）：括号配平、相对导入存在、符号与导入、重复声明、对模块自有组件的调用参数。这些排除一部分错误，不能替代编译和测试。
- **没验证**：页面交互在真机上的表现（没有组件测试覆盖向导与开牌流程）；所有 AI 功能没有用真实模型跑过，
  中文输入下 JEV 的打分质量（据公开评测它对英文最强，指令用英文、内容保持中文）；非 Android 平台读不到 JEV 密钥，会自动回落。
