# 照见（Zhaojian）模块审计

基线：`origin/codex/contextual-action-forecast-v3-20261008@641b0d17`（拉取时提交时间最新的分支；`main` 是它的祖先）。
功能清单与完成占比见 `PORTING.md`（由 `tools/porting.py` 从清单算出，不凭感觉）。

## 做了什么

web 原型（叔本华「性格 × 动机局面 → 决定 → 行为」因果链）移植为独立 Flutter 模块，接在「发现」页。
五组入口：**选择 / 行动 / 改变 / 我 / 方向**，共 25 个页面，首页只显示已注册的页面。

| 组 | 页面 |
|---|---|
| 选择 | 决策（六步：写选择、补全动机、体验卡、天平与冲突诊断、一致度与难度、封存预测）、信念检验（远期汇票） |
| 行动 | 未开的牌（现场速查、开牌、自知分、回放）、行为记录、知行（落差诊断、愿望漏斗、念头省察）、回望（悔恨诊断、手段检查） |
| 改变 | 改变引擎、计划与复盘、绳子、小墙与假设行动、接受、认知重构 |
| 我 | 自画像、证据（行为考古、他人观察、自述线索）、主线与假设、AI 分析、决策方式、变化、签名、原理 |
| 方向 | 目标链、一条线、探测、放弃拆分器、成长回顾 |

贯穿的机制：反宿命论护栏、绝望或自伤迹象即停下并转向求助、行为证据门槛、动态下一步与分散度提醒、
AI 引擎适配（JEV → AI 模拟 → 规则）、引擎预测的三方揭示、签名与决策联动。

## 决策引擎

宿主层 `lib/zhaojian_host/`，模块本体不碰网络和密钥：

- **打分**优先用真实的 **JEV（System One）**，复用「证据成长」里已启用、已配置的密钥；每个候选一个独立的 score 问题，每批 12 题。
  JEV 不可用（没启用、没密钥、限流、响应不合规、不足一半的候选有分数）→ 回落到通用大模型按决策引擎格式的**模拟**打分 → 再回落到规则推荐。
- **文字生成**（补全动机、AI 列选项、研判、改变方案、认知重构、AI 分析等）只走文字引擎（AI）；没有时每一处都有自己写的路径。
- **隐私**：凡是会把用户内容发给外部服务的操作，点击前都披露发给谁（`ZhaojianOracle.sendsData` / `generateLabel`）。
- 一致度与难度、AI 分析等目前只走文字引擎，**没有接 JEV**（需要 choice 题型与更复杂的回落）。
- 「AI 引擎预测」存起来、开牌前不给用户看，避免影响用户自己的判断。

## 数据

全部在本机 SQLite，表均为 `z_` 前缀，无外键：`z_meta`（版本与键值，键值键名加 `kv:` 前缀）、`z_decision`、`z_log`、`z_hyp`、`z_miss`、`z_item`。
`z_item` 是通用条目表，按 `kind` 区分十几类条目（绳子、小墙、计划、行为考古、签名……），新增一类条目不需要新表。

模块自管 schema 版本：v1 → v2 新增 `z_decision.align_json`；v3 新增 `z_item`。宿主库 35 → 36（建表）→ 37（v2）→ 38（v3）。
`migrate` 先幂等补表，再按模块记录的版本补列，已有数据保留（有测试覆盖）。
数据可以导出（复制 JSON）和从备份恢复（替换现有全部数据，事务内完成，出错回滚，丢弃当前表结构没有的列）。

## 集成契约（与火种一致）

- `lib/zhaojian/`：除 `flutter`、`sqflite` 外零外部依赖；不自己开库，不引用 `AppDatabase`。
- `lib/zhaojian_host/`：等库、注入引擎（JEV → AI 模拟 → 规则推荐）。
- `lib/data/db.dart`：onCreate 调 `ZhaojianSchema.createAll`，onUpgrade 调 `ZhaojianSchema.migrate`（均幂等）。
- `lib/pages/discover_page.dart`：入口卡片与 `_openZhaojianFromDiscover`。

## 红线与边界

不做诊断；不依据外貌、体型判断性格；身体信号只是线索；分数只是排序和对照的依据，不是结论；筹码是虚拟的，没有随机奖励；
假设行动四条红线、放弃实验两条红线；AI 分析里命中诊断、外貌、宿命式措辞的条目被丢弃而不是改写；
「自由感」统计只说明行为对自己可预测，不证明决定论。
詹姆斯五种决策、勒温/米勒冲突的措辞据二手资料整理，上线前请核对原文。

## 没做的、做了但没被真实服务验证的（如实）

- 清单（`PORTING.md`）里 45 项均已移植，没有已知的功能缺口。但清单是我自己从原型拆出来的，不是官方规格；
  功能是行为层面的对应，不是逐像素、逐字的复刻，也不保证原型里每个细枝末节都拆进了清单。
- **研判**：Choice / Score / Noul 三类独立回答，由 AI 估计，界面标明不是真实决策引擎的调用。
- **JEV**：前 5 动机打分、一致度分数（欲求 × 选项 × 时间尺度）都走真实的 JEV；难度、阶梯、外部条件是文字，JEV 给不了，由文字引擎补。
  请求结构和回落有测试（用模拟的 JEV 响应），**没有用真实密钥调用过**；中文输入下的打分质量没验证（据公开评测它对英文最强，指令用英文、内容保持中文）。
- **OpenAI Decisions API**：复用应用里已配置的 OpenAI 密钥（全局 AI 服务商为 OpenAI 时），不另存密钥。
  请求与响应格式按官方文档实现，并在 2026-10-16 重新对照了文档（`POST /v1/decisions`、`gpt-6-luna`、`score` 题的 `levels`、
  响应里 `score` 是等级下标的概率加权平均）；有测试，但**没有用真实密钥调用过**，公测接口可能变，响应不合规时自动回落。
- AI 分析、补全动机、改变方案、认知重构等是文字生成，只走文字引擎。
- 非 Android 平台读不到 JEV 密钥，会自动回落。
- 备份恢复会**替换**现有全部数据（有确认对话框，事务内完成，出错回滚）。

## 验证状态（如实）

- **编译**：每个提交都在 CI 里确认了整个 app 的 Flutter release 编译通过（`Build Android APK`，Flutter 3.35.3，不是备用的 Gradle 路径）。
  第一批里有过一次失败：重复声明（控制器里两个 `exportJson`、`ZCopy` 里两个 `threeLayers`），已修。
- **数据库**：Kindling CI 和 Zhixing Tree CI 里「打开宿主库」的测试在 schema v3 下通过。
- **测试确实被运行了**：`test/zhaojian/` 有 8 个文件、约 250 个用例。专属工作流 `zhaojian_ci.yml` 推不进仓库（令牌没有 workflow 权限），
  所以我把测试放在临时分支的 Kindling 测试目录下，借 Kindling CI 跑，并让每个失败的用例把名字和报错打成 CI 注解。
  最近一次完整运行：0 个失败，`dart analyze` 通过。为证明测试确实被执行，我还加过一条必然失败的探针用例：CI 报告「168 个通过、2 个失败」，
  比 Kindling 原有的 48 个多出 120 多个，探针的失败信息也原样读了回来。
- **组件流程测试**（`zhaojian_flow_widget_test.dart`）：按手机尺寸（360×780）渲染全部 25 个页面（空状态与有数据各一遍，布局溢出会直接失败），
  并把「记录行为 → 主线计数 → 决策六步 → 封存 → 开牌」「绳子」「接受的门槛」「认知重构的危机拦截」「改变引擎」等流程点一遍；
  另用脚本化的 AI 引擎验证 AI 列选项、前 5 动机、研判在界面上的接入。
- **这些测试发现过真问题**：认知重构和改变引擎里，出现绝望措辞时安全提示会显示，但「下一步」按钮没有同步变灰
  （危机状态只在父组件构建时算一次，打字不触发重建），已修并有测试覆盖；还有决策页标题与注册表不一致，已修。
- 静态自查（本地脚本）：括号配平、相对导入存在、符号与导入、重复声明、对模块自有组件的调用参数。
- **没验证**：真机上的实际使用；所有 AI 功能没有用真实模型跑过（只有脚本化引擎的流程测试）；JEV、OpenAI Decisions API 没有用真实密钥调用过。
  `zhaojian_ci.yml` 还需要手动加进 `.github/workflows/`，之后每次推送就会自动跑这些测试。
